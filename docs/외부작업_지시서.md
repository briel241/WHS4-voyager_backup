# MASS/ROC 응용 계층 — 외부 작업 지시서

> 이 문서는 **저장소에 접근할 수 없는 다른 Claude 채팅**에게 넘기기 위한 자립형(self-contained) 작업 명세다.
> 필요한 규약·데이터 형식·인터페이스를 모두 이 문서 안에 넣었다. 결과 코드는 이 저장소에서 다시 검증·통합한다.

---

## 0. 이 문서를 받는 Claude에게

- 당신은 이 프로젝트의 소스 파일을 볼 수 없다. 이 문서에 적힌 **규약과 형식에만 근거해** 코드를 작성하라.
- 산출물은 **순수 Python 3.10+ + 표준 라이브러리**로 작성한다. 유일한 예외는 X.509 작업의 `cryptography` 패키지이며, 없을 때를 대비한 대체 경로도 함께 만든다.
- 외부 네트워크·설치가 필요한 다른 라이브러리는 쓰지 않는다.
- 파일 경로·클래스명·함수 시그니처는 **이 문서가 지정한 그대로** 맞춘다. 통합할 때 그대로 끼워 넣을 수 있어야 한다.
- 각 작업 끝에 **표준 라이브러리 `assert`만으로 도는 테스트**를 함께 제출한다(3장 규약 참조).

## 1. 프로젝트 한 눈에

자율운항선박(MASS, 선박)과 원격운영센터(ROC, 육상)가 무선(VDE-TER) 링크로 응용 계층 데이터를 주고받는다. 우리는 **응용 계층 + PI(Presentation Interface)** 를 맡고, 링크·물리 계층(`VDETER/`)은 팀원이 맡는다.

```
ROC(육상) ──[응용 payload bytes]──▶ VDE-TER 링크 ──▶ MASS(선박)
   행위자                              (우리 관할 밖)        행위자
   RocAgent                                                  MassAgent
```

- 행위자는 **payload(바이트)** 를 만들고, 누구에게 보낼지·ACK가 필요한지만 정한다. 링크에 어떻게 실리는지는 모른다.
- **두 가지 메시지 계열이 있다. 헷갈리지 말 것:**

  | 계열 | 예 | 형식 | 상태 |
  |---|---|---|---|
  | **A. 비트 패킹 메시지** | 위치보고·항로지시·ACK·항행경보·환경·기상 | 우리 codec의 봉투 `[VPFI 16 | Message ID 8 | 본문 | padding]` | 구현됨 |
  | **B. 원시 payload 포맷** | **X.509 인증서(DER)**, AIS 인증값(82 byte) | 링크가 포맷별로 직접 인식, 우리 봉투 없음 | AIS 인증값만 구현, **인증서 미구현** |

  → 이번 작업의 **작업 A(인증서)는 계열 B**다. 비트 봉투로 감싸지 말고 **원시 바이트(DER)를 그대로 payload로** 다룬다.

## 2. 현황 vs 요청 대비표

당신(외부 Claude)이 새로 만들 것은 **굵게** 표시했다.

| # | 요청 항목 | 현재 상태 | 이번에 할 일 |
|---|---|---|---|
| 1a | 공개키 인증서 송수신 (ITU-T X.509 v3) — `SC-VDE-001` | 시나리오 문서·설계·`X509_CERTIFICATE` data_type·ECDSA 서명 백엔드는 **있음**. 인증서 생성/파싱/검증·행위자 흐름은 **없음** | **작업 A** — 인증서 생성·전송·검증·신뢰저장소 반영 흐름 전체 |
| 1b | 노선 계획 교환 (S-421) — `SC-VDE-005` | 항로지시(Message ID 2)+ACK(ID 3) **구현·테스트 통과**. 압축 비트 형식 | **작업 B** — 논리 JSON 모델의 메타데이터 상관(routeID/editionNo) 보완 검토 |
| 1c | MASS-ROC 원격 조종 (S-421 하위) | 항로지시 확장(heading/fallback/turn_radius/plan_SOG/geometry)+S-421 ACK 코드 **구현** | **작업 B에 포함** — 조작 데이터 JSON과 압축형식 필드 정합 확인 |
| 2 | 시나리오 종료 시 로그 기록·분석 | ROC 관찰 기록기(`recorder`)+HTML 보고서(`report`) **있음** (항적·시계열 중심) | **작업 C** — 시나리오 실행 타임라인 로그 + 합격/불합격·지연 분석 |
| 3 | 시나리오 선택·재현 인터페이스 (선택) | 개별 실행 스크립트 3종 있음, 통합 진입점 없음 | **작업 D(선택)** — 시나리오 목록에서 골라 실행→로그/보고서 산출 |

## 3. 반드시 지킬 코딩 규약

### 3.1 비트 필드 API (계열 A 메시지에서만 사용)

우리 저장소에 이미 있는 헬퍼다. 시그니처만 알면 된다. **재작성하지 말고 아래처럼 호출**하는 코드를 쓰라(통합 시 실제 구현으로 연결됨).

```python
# common/bitfield.py 에 이미 존재. import 해서 쓴다.
writer = BitWriter()
writer.write_uint(value: int, bit_size: int, field: str = "value")   # 부호 없는 정수
writer.write_int(value: int, bit_size: int, field: str = "value")    # 2의 보수 부호 정수
writer.pad_to_byte()                                                  # 바이트 경계까지 0 채움
data: bytes = writer.to_bytes()

reader = BitReader(data)
reader.read_uint(bit_size: int, field: str = "value") -> int
reader.read_int(bit_size: int, field: str = "value") -> int
reader.remaining -> int      # 남은 비트 수(property)
reader.check_padding(field: str = "padding")   # 남은 비트가 0인지 확인
```

### 3.2 계열 A 메시지 모듈 템플릿

계열 A 메시지는 모두 아래 구조를 따른다. 아래는 **실제 구현된 `ais_auth.py`(SC-VDE-003)** 를 축약한 참고 템플릿이다. 새 계열 A 메시지를 만든다면 이 형태를 따른다.

```python
# common/messages/<이름>.py
from __future__ import annotations
from dataclasses import dataclass
from ..bitfield import BitReader, BitWriter

MESSAGE_ID = 4          # registry에서 배정. 기존: 1위치보고 2항로 3ACK 4AIS인증 5경보 6환경 7기상
NAME = "AIS Auth/Integrity"

FIELD_A_BITS = 30       # 각 필드 비트 폭을 상수로 선언
BODY_BITS = FIELD_A_BITS + ...   # 본문 총 비트

@dataclass
class MyMessage:
    field_a: int
    # ... 검증은 __post_init__에서

def write_body(writer: BitWriter, message: MyMessage) -> None:
    writer.write_uint(message.field_a, FIELD_A_BITS, "Field A")
    # ... 필드 순서대로

def read_body(reader: BitReader) -> MyMessage:
    field_a = reader.read_uint(FIELD_A_BITS, "Field A")
    return MyMessage(field_a=field_a, ...)

def describe(message: MyMessage) -> str:      # 콘솔 표시용
    return f"Field A: {message.field_a}"
```

등록은 두 곳에서 한다(문서에 지시가 있을 때만):
- `common/messages/registry.py` — `MESSAGE_CODECS[MESSAGE_ID] = 모듈`, `MESSAGE_IDS[dataclass] = MESSAGE_ID`
- `common/codec.py` — `ApplicationMessage` Union에 dataclass 추가

### 3.3 송신 요청(Outbound) 계약

행위자가 만드는 송신 요청. **링크 계층 값(Link ID·Type·VPFI 등)을 넣지 않는다.**

```python
# common/outbound.py 에 이미 존재
BROADCAST_ID = 0
DATA_TYPE_X509_CERTIFICATE = "X509_CERTIFICATE"       # 인증서용 — 이미 예약됨
DATA_TYPE_AIS_AUTH_INTEGRITY = "AIS_AUTH_INTEGRITY"

@dataclass
class Outbound:
    payload: bytes
    destination_id: int = BROADCAST_ID
    ack_required: bool = False
    data_type: str | None = None      # 위 상수 중 하나 또는 None
    content_type: str | None = None   # 예: "application/pkix-cert"
    label: str = ""
    # 규칙: broadcast(destination=0)에는 ack_required=True 금지
```

### 3.4 산출물·테스트 규약

- 테스트는 **표준 라이브러리만** 사용(`assert` 문 나열, `if __name__ == "__main__":`로 실행). 예: `python3 tests/test_xxx.py` 하면 통과 시 조용히 끝나고 실패 시 AssertionError.
- 기존 테스트 스타일: 라운드트립(encode→decode 후 값 일치), 경계값, 실패 케이스.
- 주석·문서화 문자열은 **한국어**로. 표준 근거가 있으면 근거를 함께 적는다.
- 외부 의존성은 `cryptography` 외 금지.

## 4. 작업 A — X.509 인증서 송수신 (`SC-VDE-001`)

### 4.1 목적

ROC가 MASS에게 서명 검증에 쓸 **X.509 v3 ECDSA 공개키 인증서**를 전달한다. MASS는 받은 인증서를 **검증한 뒤에만** 신뢰 저장소에 반영한다. 이 시나리오는 다른 모든 보안 시나리오의 전제다.

### 4.2 이것은 계열 B(원시 payload)다

인증서는 우리 비트 봉투로 감싸지 **않는다.** payload는 **인증서 DER 바이트 그대로**이고, 링크는 이를 `x509.certificate_report` 포맷으로 인식한다. 응용이 하는 일은 논리적으로 두 줄이다.

```python
# ROC 측
outbound = Outbound(payload=certificate_der, destination_id=MASS_ID,
                    ack_required=True, data_type=DATA_TYPE_X509_CERTIFICATE,
                    content_type="application/pkix-cert")
# MASS 측
if received.data_type == "X509_CERTIFICATE":
    ok, reason = verify_and_store(received.payload)
```

분할·재조립·자원할당은 전부 링크(VDE-TER Service) 내부 일이다. **응용은 DER 바이트만 다룬다.**

### 4.3 암호 파라미터 — 선택 불가 (ITU-R M.2092-2 §A4-4.15)

| 항목 | 값 |
|---|---|
| 공개키 알고리즘 | `id-ecPublicKey` |
| 곡선 | **secp256r1** (P-256) |
| 공개키 크기 | 256 bit |
| 발급자 서명 | **ecdsa-with-SHA256** |
| 서명 인코딩(전송용) | IEEE P1363 고정 길이 연접 (r‖s, 각 32 byte = 64 byte) |
| 인증서 지문 | signatureValue 최하위 **48 bit(6 byte)** |
| 인증서 최대 크기 | 1,024 byte |

X.509 확장 필드에 담을 것: **MASS ID, ROC ID, MMSI, IMO 번호**.

### 4.4 만들 파일

**`common/security/certificate.py`** — 인증서 생성·파싱·검증. 시그니처를 아래로 고정한다.

```python
from dataclasses import dataclass

@dataclass
class CertificateInfo:
    subject: str            # 인증 대상(예: "MASS-440123456")
    issuer: str             # 발급자(예: "ROC-CA")
    serial_number: int
    not_before: float       # epoch seconds (UTC)
    not_after: float
    public_key_der: bytes   # 대상의 공개키(SubjectPublicKeyInfo, DER)
    fingerprint: bytes      # 48-bit(6 byte), signatureValue 최하위 48 bit
    # 확장 필드
    mass_id: str | None = None
    roc_id: str | None = None
    mmsi: str | None = None
    imo: str | None = None

def build_certificate(
    subject: str, issuer: str,
    subject_public_key,          # 대상 공개키 객체
    issuer_private_key,          # 발급자(CA) 개인키 — 이 키로 서명
    serial_number: int,
    not_before: float, not_after: float,
    *, mass_id=None, roc_id=None, mmsi=None, imo=None,
) -> bytes:
    """X.509 v3 ECDSA(secp256r1/SHA256) 인증서를 DER 바이트로 만든다.
       확장 필드에 mass_id/roc_id/mmsi/imo를 넣는다. 크기 1,024 byte 초과 시 ValueError."""

def parse_certificate(der: bytes) -> CertificateInfo:
    """DER를 파싱해 CertificateInfo로 돌려준다."""

def verify_certificate(der: bytes, trust_anchor_der: bytes, now: float) -> tuple[bool, str]:
    """발급자 서명을 trust_anchor의 공개키로 검증하고 유효기간을 확인한다.
       반환: (성공여부, 사유). 사유 예: "ok" / "bad-signature" / "expired" /
       "not-yet-valid" / "too-large" / "parse-error"."""

def fingerprint_of(der: bytes) -> bytes:
    """인증서 signatureValue 최하위 48 bit(6 byte)를 돌려준다."""
```

구현 지침:
- **표준 경로**: `cryptography` 패키지(`x509`, `hazmat.primitives.asymmetric.ec`)로 실제 X.509 v3 DER를 생성/파싱/검증한다. 곡선 `SECP256R1`, 해시 `SHA256`.
- **대체 경로**: `cryptography`가 없으면 `ImportError`를 잡아, 같은 인터페이스를 유지하되 **간이 자기 정의 DER 유사 구조**(예: 필드를 정해진 순서로 직렬화하고 HMAC-SHA256로 "서명")로 동작하는 백엔드를 쓴다. 이때 `verify_certificate`는 여전히 (성공,사유)를 돌려줘야 하고, 성공/실패/만료/위조를 구분할 수 있어야 한다. **대체 경로는 실제 공개키 암호가 아님을 모듈 상단 주석에 명시**한다(테스트·데모용).
  - 우리 저장소의 `common/security/signature.py`에 이미 이런 이중 백엔드 패턴이 있다: `default_backend()`가 `cryptography` 있으면 `EcdsaP256Backend`(is_standard=True), 없으면 `TestHmacBackend`(is_standard=False)를 준다. **가능하면 그 백엔드를 재사용**하도록 `from ..security import signature as sig` 하고 `sig.default_backend()`를 쓰라. (그 모듈의 존재만 가정하고, 세부 구현은 우리가 연결한다.)

**`common/security/trust_store.py`** — 신뢰 저장소.

### 4.5 행위자 흐름 (핵심)

우리 `RocAgent`/`MassAgent`에 붙일 **메서드 형태**로 작성하되, 외부에서는 저장소를 못 보므로 **독립 함수 + 작은 데모**로 제출한다. 함수 시그니처:

```python
def roc_issue_certificate(cert_der: bytes, mass_id: int) -> Outbound:
    """ROC가 인증서 전송 요청을 만든다. data_type=X509_CERTIFICATE, ack_required=True."""

def mass_receive_certificate(cert_der: bytes, trust: TrustStore,
                             trust_anchor_der: bytes, now: float) -> tuple[bool, str]:
    """MASS가 인증서를 검증하고 통과 시에만 trust에 반영한다.
       ITU §A4-4.15: 검증 실패 시 '수신하지 않은 것처럼' 처리 — 저장소 불변."""
```

검증 순서(중요): **저장소 변경 전에 검증**한다. 실패하면 기존 저장소를 건드리지 않는다.

### 4.6 수용 조건 (테스트로 증명)

`tests/test_certificate.py`:
1. 생성→파싱 라운드트립: `build_certificate`로 만든 DER를 `parse_certificate` 하면 subject/issuer/유효기간/확장(MMSI 등)이 일치.
2. 정상 검증: CA가 서명한 인증서를 그 CA(trust anchor)로 `verify_certificate` 하면 `(True,"ok")`.
3. 위조 탐지: 인증서 바이트 1개를 뒤집으면 `(False,"bad-signature")`.
4. 만료: `not_after`가 `now`보다 과거면 `(False,"expired")`; `not_before`가 미래면 `(False,"not-yet-valid")`.
5. 신뢰저장소 멱등: 같은 인증서 두 번 `add` 해도 항목 1개. 검증 실패 인증서는 `mass_receive_certificate` 후 저장소에 **없어야** 한다.
6. 크기 한계: 1,024 byte 초과 payload는 거부.
7. `cryptography` 유무 두 경로 모두에서 1~6이 동작(대체 경로는 "표준 아님" 표식과 함께).

## 5. 작업 B — S-421 노선 계획 / 원격 조종 정합

### 5.1 현재 구현 요약 (이미 있음 — 재작성 금지)

- **항로지시 메시지(Message ID 2, 계열 A)** 가 S-421 조작 데이터를 압축 비트로 나른다. 이미 담는 필드:
  - 공통: 목표 heading setpoint(12 bit), fallback 상태(3 bit: 0=none/1=Anchoring/2=DynamicPositioning/3=Drifting)
  - 웨이포인트별: 좌표(경도 28 bit·위도 27 bit, 1/10,000분), 선회반경 turn_radius(10 bit), 계획 SOG(10 bit), leg 기하(2 bit: 0=none/1=Lexodrome/2=Orthodrome)
- **ACK 메시지(Message ID 3, 계열 A)**: 상태 코드 4 bit — `4=Acknowledged, 7=Errors, 8=Incomplete, 9=Route issues` (S-421 Edition 1.0.0 `routeInfoStatus` 코드). `0`은 S-421에 없는 본 프로젝트 예약값이며 송신하지 않는다.

### 5.2 논리 JSON 모델 (근거 자료)

원격 조종 조작 데이터·ACK의 **권장 논리 형식**은 아래 JSON이다. S-421 필드명·열거값을 재사용한다.

조작 데이터 핵심 필드:
- `sourceMMSI` / `destinationMMSI` (9자리 문자열, 선행 0 보존)
- `routeFormatVersion`("1.0"), `routeID`(문자열 고유 식별자), `routeEditionNo`(양의 정수)
- `routeInfo`: `routeInfoName`, `routeInfoAuthor`, `routeInfoEditionTime`(ISO8601 UTC), `routeInfoStatus`(3=Recommended), `routeInfoValidityStart/End`, `routeInfoVesselMMSI`
- `headingSetPoint`(0≤x<360), `routeWaypoints[]`(id·WGS84/DMM 위치·turn_radius NM·leg 기하), `routeSchedule[]`(웨이포인트별 planned SOG knot), `fallbackState`(Anchoring/DynamicPositioning/Drifting, 없으면 필드 생략)
- **좌표는 WGS84/DMM**: 위도 도0-90·분0≤m<60·반구 N/S, 경도 도0-180·분0≤m<60·반구 E/W. DD 변환: `DD = deg + min/60`, S·W면 음수.

ACK: 조작 데이터의 source/destination MMSI를 서로 바꾸고 **같은 `routeID`·`routeEditionNo`** 를 되돌린다. `routeInfoStatus`는 4/7/8/9, 오류 시 `routeInfoDescription`에 위치·사유.

### 5.3 이번에 할 일

우리 **압축 비트 형식**과 위 **논리 JSON 모델** 사이의 필드 정합만 검토·보완한다. 새 링크 프로토콜을 만들지 않는다.

1. **상관 식별 갭 분석**: 현재 압축 ACK는 상태 코드만 담고 **어떤 route에 대한 ACK인지(routeID/editionNo)를 담지 않는다.** 여러 항로가 오갈 때 ACK를 짝지으려면 참조가 필요하다. 두 안을 제시하고 하나를 추천하라:
   - (a) 압축 ACK에 짧은 route 참조 필드 추가(예: routeID 해시 하위 N bit + editionNo 소수 bit)
   - (b) 링크의 point-to-point ACK 상관에 위임하고 응용 ACK는 상태만 유지
2. **JSON ↔ 압축 변환기**(선택): 위 논리 JSON을 입력받아 우리 항로지시/ACK **필드 값 dict**로 바꾸는 순수 함수 `route_json_to_fields(json_obj) -> dict`와 역함수 `fields_to_route_json(fields) -> dict`. DMM↔1/10,000분 좌표 변환, status 코드 매핑 포함. 표준 라이브러리 `json`만 사용.
3. `tests/test_route_json_bridge.py`: JSON→fields→JSON 라운드트립에서 좌표 오차가 1/10,000분 이내, status·fallback·geometry 열거값이 보존됨을 확인.

**주의**: 압축 형식은 metadata(routeID 문자열, name, validity 시각, author)를 비트로 담지 않는다. 변환기는 **압축이 담을 수 있는 필드만** 왕복 보존하고, 나머지는 "압축 미포함"으로 분리 보고하면 된다. 억지로 비트에 넣지 말 것.

## 6. 작업 C — 시나리오 종료 로그 기록·분석

### 6.1 이미 있는 것 (참고)

`common/observe/recorder.py`(관찰 기록기)와 `report.py`(HTML 보고서, 항적·시계열 SVG)가 있다. 이들은 **ROC 관찰 중심**이라 "시나리오 한 건이 규격대로 흘렀는가"를 판정하지는 않는다. 작업 C는 이 위에 **시나리오 실행 로그·판정 계층**을 새로 얹는다. 기존 파일을 고치지 말고 새 모듈로 만든다.

### 6.2 만들 파일

**`common/observe/scenario_log.py`** — 시나리오 실행 타임라인 로거.

```python
from dataclasses import dataclass, field

@dataclass
class LogEntry:
    time: float                 # epoch seconds
    direction: str              # "ROC->MASS" | "MASS->ROC"
    kind: str                   # "send" | "recv" | "verify" | "ack" | "note"
    message: str                # 사람이 읽는 요약(예: "X509 cert frag 3/6")
    detail: dict = field(default_factory=dict)   # 임의 부가 필드

@dataclass
class ScenarioRun:
    scenario_id: str            # 예: "SC-VDE-001"
    started: float
    entries: list = field(default_factory=list)
    def log(self, entry: LogEntry) -> None: ...
    def finish(self, now: float) -> None: ...
```

수집할 항목(SC-VDE-001 시나리오가 요구하는 로그 필드에 맞춘다):
송수신 시각 · 방향 · 메시지 종류 · Source/Destination ID · (인증서일 때) fragment 번호/총개수 · 검증 결과(서명 통과 여부) · ACK/상태 코드 · 재전송 횟수 · 지연.

**`common/observe/scenario_analysis.py`** — 종료 후 분석·판정.

```python
def analyze(run: ScenarioRun, expected: dict) -> dict:
    """실행 로그를 기대치와 대조해 요약을 낸다.
       반환 예: {
         "scenario_id": ...,
         "passed": bool,
         "checks": [ {"name": "signature-verified", "ok": True}, ... ],
         "latency_seconds": {"min":.., "max":.., "mean":..},
         "retransmissions": int,
         "notes": [ ... ],
       }
    """

def to_text(summary: dict) -> str:   # 콘솔용 사람 읽는 판정문
    ...
```

판정 체크 예(시나리오별로 `expected`가 정함):
- 인증서(SC-VDE-001): 재조립 payload가 원본과 **바이트 일치**, 서명 검증 성공, 전 fragment ACK, 중복 실행 없음(멱등).
- 항로(SC-VDE-005): ACK status=4(Acknowledged), waypoint 개수 일치.

### 6.3 수용 조건

`tests/test_scenario_log.py`:
1. `ScenarioRun`에 항목을 넣고 `finish` 후 `analyze`가 정상 시나리오를 `passed=True`로 판정.
2. 서명 실패 항목을 넣으면 `passed=False`, 해당 check `ok=False`.
3. 지연 통계(min/max/mean)가 로그 시각으로부터 올바르게 계산됨.
4. `to_text`가 예외 없이 사람이 읽는 문자열을 만든다.

산출물은 **JSON 직렬화 가능**해야 한다(로그를 파일로 남길 수 있게). 표준 `json`만 사용.

## 9. PM 질문에 대한 회신 정리

PM 질문: *"원격 조종 데이터 형식이 아직 인증서 데이터 처리만 담고 있는데, 지원해야 할 데이터가 더 있으면 알려달라."*

회신 요지(우리 → PM):
- 링크(VDE-TER)가 현재 운영 지원하는 응용 포맷은 **인증서(`x509.certificate_report`)와 AIS 인증값(`ais.authentication_integrity.scheme1`, 82 byte)** 둘뿐이다.
- 추가로 링크 registry에 **포맷 등록이 필요한 것**:
  1. **S-421 항로지시**(원격 조종 조작 데이터) — 계열 A 압축 형식. 항로 교환·원격조종 시나리오의 본체.
  2. **응용 ACK**(routeInfoStatus 4/7/8/9) — 조작 데이터에 대한 응용 계층 응답.
  3. (후순위) 항행경보·환경·기상.
- 즉 **인증서만으로는 노선 계획 교환·원격 조종 시나리오를 실 링크로 못 돌린다.** 항로/ACK 포맷 등록이 다음 우선순위다.
