# 실 하드웨어(B210) 연동 착수 계획 — 3 시나리오를 진짜 전파로

> 확정 3개 시나리오(SC-VDE-001 인증서 · 005 노선 · 006 원격 조종)를 **소프트웨어 시뮬레이션이
> 아니라 실제 USRP B210 2대**로 종단 실행하기 위한 착수 계획이다. 코드 작성을 다른 세션에
> 맡기기 위한 지시서다.

---

## 0. 이 문서를 받는 사람에게 (중요)

- 이 작업은 **VDETER 링크 스택 깊숙한 실시간 통합**이다. **저장소의 `VDETER/` 소스가
  반드시 있어야 하고, 아래 §3의 파일들을 직접 읽어야 한다.** 스펙만으로 blind 작성은 불가능하다.
- **성공이 보장되지 않는다.** endpoint 타이밍/MAC은 지금까지 "가짜 시간(수동 clock)"으로만
  검증됐다. 실시간 + 실 전파에서 전체 스택이 도는지는 미검증이다. 그래서 **Phase 2를
  fail-fast 게이트**로 두었다 — 거기서 막히면 멈추고 링크 팀과 논의한다.
- **응용 계층은 이미 완성이다.** 우리 `common/vdeter_bridge.py`가 `Outbound →
  SubmitTransferRequest`를 만들고, `cert_loopback_demo.py`/`route_loopback_demo.py`가
  "전체 스택 + (소프트웨어)무선"까지 이미 증명했다. **이 작업은 그 밑의 '무선을 진짜
  B210으로' 바꾸는 launcher를 만드는 것**이다.

## 1. 지금까지 확인된 사실 (근거)

| 사실 | 근거(파일) | 의미 |
| --- | --- | --- |
| 라디오는 **config로 선택**, **B210 지원됨** | `runtime/wiring.py` `build_radio_adapter`: `RadioAdapterKind.B210 → B210RadioAdapter(...)` | 설정에 `adapter_kind="B210"` + serial/주파수/게인만 넣으면 wiring이 어댑터 생성 |
| B210 어댑터는 **자체 스레드 실시간** | `radio/b210/adapter.py`: `Thread`, `_monitor_thread`, `self._backend.poll_async()` | 소프트웨어의 수동 `process_due()`와 **구동 모델이 다름** — 실시간 |
| **단일 endpoint 조립기** 존재 | `runtime/wiring.py` `build_stage5_endpoint(dependencies, deployment, crypto_dependencies)` | PC마다 1개 endpoint를 세울 수 있음 |
| **하드웨어 arming 게이트** | `tools/run_stage3_b210_hardware_tests.py`: `VDETER_B210_HARDWARE_TEST=1` + 환경 검증 | TX는 명시적으로 무장(arm)해야 허용 — 안전장치 |
| **fixture preflight 필수** | `radio/b210/preflight.py`: `preflight outcome은 PASS여야 TX 허용` | 감쇠기/케이지/전력 검증을 통과해야 송신 가능 |
| **소프트웨어 그룹 = 1 프로세스·공유 medium·수동 clock** | `tests/support/stage5.py`: `build_stage5_software_group`, `drive_stage5_group` | 이 구조를 **PC별·실시간·무 medium**으로 바꾸는 게 핵심 |

**결론**: 라디오 어댑터·단일 endpoint·안전 게이트는 이미 있다. 새로 만들 것은 **(a) 실시간
구동 루프**, **(b) PC별 launcher**, **(c) 우리 시나리오 연결부**이다.

## 2. 목표 아키텍처

```
[송신 PC = ROC]                                  [수신 PC = MASS]
 build_stage5_endpoint                            build_stage5_endpoint
   radio.adapter_kind = "B210" (serial A)           radio.adapter_kind = "B210" (serial B)
   time_source = SystemTimeSource (실시간)           time_source = SystemTimeSource
        │                                                 │
   실시간 구동 스레드(새로 만듦)                        실시간 구동 스레드
        │                                                 │
   B210RadioAdapter ── TX ──▶ [감쇠기/케이지 통과 공중] ──▶ RX ── B210RadioAdapter
        │                                                 │
   ROC: vdeter_bridge로 SubmitTransferRequest submit    MASS: DATA_RECEIVED → 우리 앱이 검증·저장
```

- **두 PC, 각 1 endpoint.** 소프트웨어처럼 한 프로세스에 3국을 넣지 않는다. 공유 medium이
  없다 — 실제 공중 전파로 주고받는다.
- **MAC/TDMA·불리틴 보드(TBB) 획득은 두 endpoint가 실 전파로 스스로 맞춘다.** ← 최대 리스크(§Phase 2).

## 4. 단계별 계획 (fail-fast 게이트 포함)

### Phase 0 — 환경·안전 준비
1. 한 PC에서 UHD/`cryptography`/B210 의존성 확인: `B210RadioAdapter.missing_dependencies()`가
   빈 튜플이어야 한다. `uhd_find_devices`로 각 PC의 serial 확보.
2. 물리 결선: `B210-A[TX/RX] ─ 30dB 감쇠기 ─ 동축 ─ [RX2]B210-B` (안테나 금지). 두 PC.
3. **fixture preflight** 실행·PASS 확인(`preflight.py`). 감쇠기/케이지/전력 검증. **PASS 없이 TX 금지.**
4. 하드웨어 arming 환경변수 설정(`VDETER_B210_HARDWARE_TEST=1` 등, `run_stage3_b210_hardware_tests.py` 참고).
   - **검증 게이트 0**: 기존 `tools/run_stage3_b210_hardware_tests.py`(무선 계층 하드웨어 gate)가
     **먼저 PASS**해야 한다. 이게 실패하면 하드웨어/결선 문제이니 여기서 멈춘다.

### Phase 1 — 단일 endpoint 실시간 구동 (한 PC)
5. `b210_configuration`로 B210 config(serial/주파수/게인) 생성 → `build_stage5_endpoint`로
   endpoint 1개 조립. `time_source = SystemTimeSource`(실시간).
6. **실시간 구동 루프(핵심 신규 작성)** — `drive_stage5_group`의 수동 clock 루프를 대체한다.
   실시간 스레드가 반복적으로: SystemTimeSource로 시각 진행 → `stage4.advance_clock()` →
   `fire_due_timers()` → `stage4.pump()` → B210 어댑터의 async 이벤트 반영. (B210 어댑터의
   monitor thread가 이미 도므로, 그 이벤트를 endpoint에 흘려넣는 접점을 `endpoint.py` 읽고 맞춘다.)
   - **검증 게이트 1**: endpoint가 crash 없이 실시간으로 start되고, radio가 `RUNNING`으로 뜨는가.

### Phase 2 — 2 PC TBB 공중 획득 ⚠️ **최대 리스크·fail-fast**
7. 두 PC에서 각각 endpoint(ROC·MASS)를 실시간 구동. 둘이 **공중 전파로 canonical TBB를
   획득·TDMA 동기**하는지 확인(`start_stage5_group`가 소프트웨어에서 하던 걸 실 전파로).
   - **검증 게이트 2 (가장 중요)**: 두 endpoint의 `stage4.mac.state.active_tbb`가 실제로
     채워지는가. **채워지면 큰 산을 넘은 것.** 안 채워지면 → **여기서 멈추고 링크 팀과 논의**.
     실시간 타이밍/동기 문제는 VDETER(링크) 코드 수정이 필요할 수 있다(우리 범위 밖).

### Phase 3 — 한 시나리오 종단 (인증서부터)
8. TBB 획득 후, ROC PC에서 우리 시나리오 payload를 submit한다. **인증서(SC-VDE-001)** 로 시작:
   `cert_flow.roc_issue_certificate_report(...)` → `vdeter_bridge.to_submit_request(...)` →
   `endpoint.submit(...)`. (loopback 데모와 동일, 대상만 실 endpoint.)
9. MASS PC에서 `ServiceEvent(DATA_RECEIVED)`를 받아 `vdeter_bridge.inbound_from_received` →
   `cert_flow.mass_receive_certificate_report`로 검증·저장.
   - **검증 게이트 3**: byte 일치 수신 + 서명 검증·저장 성공. loopback 데모 결과와 동일해야 한다.

### Phase 4 — 3 시나리오 전부
10. 노선(SC-VDE-005)·원격조종(SC-VDE-006)도 같은 방식으로 submit/수신. `route_loopback_demo.py`의
    payload 생성부 재사용. 각 시나리오 로그를 남긴다(우리 `scenario_log`·`scenario_analysis` 재사용 가능).

## 6. 안전 규칙 (반드시)

- **안테나 금지.** 반드시 `TX/RX ─ 30dB 감쇠기 ─ 동축 ─ RX2` 직결 또는 Faraday Cage.
- **fixture preflight PASS 없이는 TX 금지**(`preflight.py`). Phase 0-3에서 확인.
- 하드웨어 arming 환경변수 없이는 TX가 거부됨 — 의도된 안전장치이니 우회하지 말 것.
- 게인은 낮게 시작(수신단 보호). `run_stage3_b210_hardware_tests.py`의 승인 값 참고.

## 7. 리스크와 폴백

| 리스크 | 징후 | 폴백 |
| --- | --- | --- |
| **실시간 TDMA 동기 실패** (최대) | Phase 2에서 `active_tbb`가 안 채워짐 | **멈추고 링크 팀과 논의.** 실시간 타이밍은 VDETER 코드 수정 필요할 수 있음 |
| endpoint가 실시간(지터) 시간에서 오동작 | 타이머·MAC 예외, 재조립 실패 | 스텝 크기·게인·주파수 조정. 안 되면 링크 팀 |
| 인증서 분할이 실 RF에서 손실 | Phase 3에서 재조립 실패 | 게인/SNR 조정. 노선·조종(작은 메시지)부터 검증 후 인증서 |
| B210 백엔드 의존성 미충족 | `missing_dependencies()`가 비어있지 않음 | UHD/드라이버 설치 |

**요약**: 라디오 어댑터·단일 endpoint·안전 게이트는 갖춰져 있어 **응용→B210 연결 launcher를
새로 쓰면 될 가능성이 높다.** 단 **Phase 2(실 전파 TDMA 동기)** 가 미검증 관문이다. 여기까지
통과하면 3 시나리오 종단이 열리고, 막히면 그 지점이 정확히 링크 팀과 협업할 지점이다.
