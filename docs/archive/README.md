# 보관 문서

역할이 끝난 문서를 지우지 않고 여기 둔다. **작업 기록**으로서 가치가 있기 때문이다 —
논문·발표에서 "왜 이렇게 결정했나"를 되짚을 때 근거가 된다.

> ⚠️ **여기 있는 내용은 현재 구현과 다를 수 있다.** 최신 상태는
> [`../인수인계.md`](../인수인계.md)와 [`../사용법.md`](../사용법.md)를 본다.

| 문서 | 무엇이었나 | 왜 보관으로 옮겼나 |
| --- | --- | --- |
| `시나리오_목록.xlsx` | 8종 후보 시절의 서비스별 시나리오 카탈로그 | 확정 3종으로 좁혀지면서 [`../시나리오_카탈로그_확정3종.xlsx`](../시나리오_카탈로그_확정3종.xlsx)가 대체. 조작 데이터가 `SC-VDE-014`로 잡혀 있던 판이다 |

| `hello_bpsk_check.md` | GNU Radio BPSK 송수신 점검 절차 | `grc/`가 gitignore되어 저장소에 없다. RF 벤치를 다시 할 때 로컬 `grc/`와 함께 참조한다 |

## 지우지 않은 이유

프로젝트가 **직렬 흐름**(모사 링크 → 취약점 분석 → 공격 → 개정안 → 방어 평가)이라,
뒤 단계에서 앞 단계의 판단 근거를 다시 볼 일이 생긴다. 특히 `작업B_ACK상관_갭분석.md`는
"왜 상관 필드를 안 넣었나"를 설명하는 유일한 기록이다.
