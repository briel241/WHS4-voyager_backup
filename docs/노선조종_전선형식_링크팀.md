# 노선(SC-VDE-005)·원격조종(SC-VDE-006) 전선 형식 — 링크 팀 전달용

> 노선/조종 payload용 codec·payload_format을 만들기 위한 바이트 규격.
> 근거 코드: `route_instruction.py`·`application_ack.py`·`codec.py`·`coordinates.py`.
> 논리 모델(참고, 선택): `mass_roc_control_and_ack_message_format.md`.

## 1. 개요

- **노선(005)·조종(006)은 같은 메시지**(Message ID 2, `Route Instruction`). 조종은
  Heading Setpoint·Fallback State를 **채우고**, 노선은 **비운다(N/A)**. 나머지 구조 동일 →
  **codec 하나로 둘 다** 처리하고, 구분·업무 판정은 응용(MASS/ROC) 몫.
- **ACK는 별도**(Message ID 3).
- 필드는 S-421 이름·열거값 차용, 좁은 슬롯용 **압축 비트**(S-421 GML 아님).

## 2. 봉투

```text
[ VPFI 16 bit | Message ID 8 bit | 본문 | byte 정렬 padding ]
```

- 현재 VPFI = `0xFF01`(placeholder, 정식 R1027 값 아님). Message ID: 노선/조종=`2`, ACK=`3`.
- **운영 전환 권장**: 우리가 16-bit VPFI를 제거 → 응용 body = `[Message ID | 본문 | padding]`,
  링크 codec이 route용 VPFI/wire prefix를 붙이고 body를 검증(인증서 codec 방식). opaque
  시험 중엔 VPFI 포함 그대로 나른다(§6 벡터가 그 형태).

## 3. 노선/조종 본문 — Message ID 2

big-endian bit(MSB first). **고정부 76 bit + 웨이포인트당 77 bit + byte padding.**

### 3.1 고정부 (76 bit)

| 필드                    | bit | 형식   | 값·N/A                                                                                             |
| --------------------- |:---:| ---- | ------------------------------------------------------------------------------------------------- |
| Message Linkage ID    | 10  | uint | 0=N/A. ACK 상관 ID                                                                                  |
| Sender Classification | 3   | uint | 0=ship, 1=authority                                                                               |
| Route Type            | 5   | uint | 0=N/A,1=mandatory,2=recommended,3=alternative,4=rec-through-ice,5=ship-route-plan,31=cancellation |
| Start Month           | 4   | uint | 0=N/A (1–12)                                                                                      |
| Start Day             | 5   | uint | 0=N/A (1–31)                                                                                      |
| Start Hour            | 5   | uint | 24=N/A (0–23)                                                                                     |
| Start Minute          | 6   | uint | 60=N/A (0–59)                                                                                     |
| Duration              | 18  | uint | 262143=N/A (분)                                                                                    |
| **Heading Setpoint**  | 12  | uint | 3600=N/A, ×10→0.1° (0–359.9°). **조종에서 사용**                                                        |
| **Fallback State**    | 3   | uint | 0=none,1=Anchoring,2=DynamicPositioning,3=Drifting. **조종에서 사용**                                   |
| Number of Waypoints   | 5   | uint | 0–16 (=n)                                                                                         |

### 3.2 웨이포인트 (n번 반복, 각 77 bit)

| 필드           | bit | 형식        | 값·N/A                           |
| ------------ |:---:| --------- | ------------------------------- |
| Longitude    | 28  | int(2의보수) | 181°=108,600,000 → N/A          |
| Latitude     | 27  | int(2의보수) | 91°=54,600,000 → N/A            |
| Turn Radius  | 10  | uint      | 1023=N/A, ×100→0.01 NM          |
| Planned SOG  | 10  | uint      | 1023=N/A, ×10→0.1 kn            |
| Leg Geometry | 2   | uint      | 0=none,1=Lexodrome,2=Orthodrome |

**좌표 인코딩**: `raw = round(도 × 600,000)` (1도=60분×10,000단위), 28/27-bit 2의 보수.
남·서 반구는 음수. 복원: `도 = raw / 600,000`.

## 4. ACK 본문 — Message ID 3 (17 bit + padding)

| 필드                 | bit | 형식   | 값                                                              |
| ------------------ |:---:| ---- | -------------------------------------------------------------- |
| Message Linkage ID | 10  | uint | 원 노선의 linkage_id (상관)                                          |
| Status             | 4   | uint | 0=received,4=Acknowledged,7=Errors,8=Incomplete,9=Route issues |
| Reason             | 3   | uint | 0=none,1=route_unsuitable,2=expired,3=not_authorized           |

## 5. 예시 벡터 (검증용, VPFI 포함)

앞 3바이트 `FF 01 02` = VPFI(0xFF01)+Message ID(2). 디코드해 아래 값이 나오면 정합.

**노선(005)** — linkage 7, mandatory, 조종필드 없음, WP 2개 / 32 byte
`디코드: WP1 129.076°/35.102° SOG12.5 Lexodrome, WP2 129.333°/35.208° SOG8.0 Orthodrome`

```text
FF 01 02 01 C8 40 18 F3 FF FF E1 00 24 9D B9 E0 28 2B CA 01 90 FA A5 00 A1 C1 42 56 C0 1E 05 08
```

**조종(006)** — linkage 7, heading 92.5°, fallback Anchoring, WP 2개 / 32 byte
`디코드: heading 92.5° fallback Anchoring, WP1 SOG6.0, WP2 SOG4.0`

```text
FF 01 02 01 C8 40 18 F3 FF FF 39 D2 24 9D 7C F0 28 2B 34 00 F0 78 A4 EF 91 01 41 A6 F8 07 82 84
```

**ACK(003)** — linkage 7, status 4(Acknowledged), reason 0 / 6 byte

```text
FF 01 03 01 D0 00
```

## 6. 요청

1. **route/control codec + payload_format 등록** — 위 형식으로 body를 인식·검증(인증서
   `certificate_report` codec에 대응). Message ID 2(노선/조종)·3(ACK) 처리.
2. **VPFI 배정** — 프로젝트 전용값. 배정되면 우리가 `codec.py`의 16-bit VPFI를 제거해
   응용 body를 `[Message ID | 본문 | padding]`으로 맞춘다.
3. 등록 후 우리 작업은 `vdeter_bridge.py` 매핑 한 줄 추가 → 노선·조종이 opaque가 아닌 **운영 종단**.

> 구조 검증 범위는 codec 정책(최소 Message ID·waypoint 수(0–16)·길이 일치). 신뢰·업무
> 판정(항로 유효성 등)은 응용 책임.
