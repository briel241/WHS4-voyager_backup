# 비트 스트림 송수신 (Hello 링크)

B210 2대로 `"Hello"`를 주고받아 비트가 실제로 오가는지 확인하는 구성.
VDE-TER 구현 전 링크 점검용임.

## 파일

| 파일                          | 용도                           |
| --------------------------- | ---------------------------- |
| `grc/hello_tx.grc`          | 송신 (Node A)                  |
| `grc/hello_rx_preamble.grc` | 수신 — 프리앰블 O, 콘솔 출력. **이걸 씀** |
| `grc/hello_rx.grc`          | 수신 — 프리앰블 X, 파일 저장. 구버전      |
| `tools/find_pattern.py`     | 구버전이 저장한 파일 확인용              |

## 프레임

```
[ F9 A8 ][ H e l l o ]
  2바이트     5바이트
```

수신기가 비트 흐름에서 `F9 A8`을 찾고 그 뒤 40비트를 페이로드로 읽음.
프리앰블 없으면 어디서 끊을지 몰라 글자가 깨짐.

## 신호 흐름

**송신**

```
[Vector Source] → [Constellation Modulator] → [Multiply Const] → [USRP Sink]
 F9A8 + Hello     비트풀기(MSB)+차동+BPSK+RRC      진폭             RF
```

**수신**

```
[USRP Source] ─┬→ [Frequency Sink]                         신호 확인용
               └→ [RRC] → [Symbol Sync] → [Costas] ─┬→ [Const Sink]
                                                     ↓
     [Const Decoder] → [Diff Decoder] → [Correlate F9A8] → [Payload Console]
        점 → 비트          차동 복원         시작점 태그        5바이트 출력
```

**순서 주의** — 프리앰블 검출은 반드시 Differential Decoder 뒤에 와야 함.
송신이 프리앰블까지 차동 부호화하므로 되돌린 뒤라야 `F9 A8`이 보임.

**차동 부호화를 쓰는 이유** — BPSK는 점이 2개뿐이라 수신기가 좌우를 반대로
잡으면 전체 비트가 뒤집힘. "0/1"이 아니라 "앞 비트와 같은가/다른가"로
보내면 뒤집혀도 복원됨.

## 파라미터

송수신이 같아야 하는 값. 하나라도 다르면 아예 수신 안 됨.

| 값             |                                    |
| ------------- | ---------------------------------- |
| `samp_rate`   | 1e6                                |
| `sps`         | 4                                  |
| `excess_bw`   | 0.35                               |
| `center_freq` | 157.2e6                            |
| `bpsk`        | BPSK 성상도                           |
| 프리앰블          | `[249,168]` ↔ `'1111100110101000'` |

환경에 맞게 조절하는 값.

| 값                   |                                     |
| ------------------- | ----------------------------------- |
| `tx_gain`           | 40 — 안 되면 여기부터 올림                   |
| `tx_ampl`           | 0.5                                 |
| `rx_gain`           | 40                                  |
| `tx_dev` / `rx_dev` | `'serial=34D03DD'` 또는 `'type=b200'` |

`center_freq`를 157.2 MHz로 둔 이유 — 두 B210의 발진기 차이는 주파수에 비례함.
157.2 MHz면 약 125 Hz, 1 GHz면 약 800 Hz. Costas가 800 Hz도 감당은 하지만
낮은 쪽이 안전.

## 실행

```bash
cd "/Users/pmy/보이저 3호/voyager_3"
grcc -o grc grc/hello_tx.grc
grcc -o grc grc/hello_rx_preamble.grc
```

Node A: `python3 grc/hello_tx.py`
Node B: `python3 grc/hello_rx_preamble.py`

수신 터미널에 `Decoded message: Hello`가 반복되면 성공.

> 안테나 꽂지 말 것. `TX/RX ─ 30dB 감쇠기 ─ 동축 ─ RX2`로만 연결.
> 감쇠기 없이 직결하면 수신단 손상됨.

## 화면

| 창       | 정상                           |
| ------- | ---------------------------- |
| 송신 스펙트럼 | 가운데 봉우리                      |
| 수신 스펙트럼 | 가운데 봉우리. 평평하면 `tx_gain` 올릴 것 |
| 성상도     | 좌우 두 덩어리. 원이면 Costas 미잠김     |

수신 스펙트럼이 디버깅 1순위. 여기 봉우리 없으면 뒤쪽 블록은 전부
잡음 처리 중이라 볼 필요 없음.

## 실측 — tx_gain 결정

구버전으로 캡처해서 `find_pattern.py`로 확인. RX 게인 40, 감쇠기 30 dB.

| tx_gain | 캡처      | 검출     | 최대 연속 | 분포                |
| ------- | ------- | ------ | ----- | ----------------- |
| 20      | 2.65 MB | **0건** | —     | 신호 없음             |
| 30      | 3.20 MB | 17,567 | 839회  | `████······` 앞부분만 |
| 40      | 0.43 MB | 6,270  | 434회  | `██████████` 전 구간 |

건수만 보면 30이 많지만 캡처 크기가 7배 차이임. 밀도로는 40이 2.7배 우수
(14.6 vs 5.5 건/1000바이트). 결정적인 건 분포 — 30은 앞 40%에만 몰려 중간에
링크를 놓쳤고 40은 끝까지 물고 있었음. **40 채택.**

## 프리앰블을 넣게 된 이유

위 실측에서 8가지 정렬 **전부**에서 `Hello`가 검출됨. 정상이면 하나만 나와야 함.

```
tx_gain 40   정렬0 5308 / 1 5936 / 2 5139 / 3 5079
             정렬4 5455 / 5 4984 / 6 5377 / 7 6270
```

Symbol Sync가 심볼을 가끔 하나 더/덜 세면(슬립) 그 순간부터 비트 경계가 1칸 밀림.
긴 캡처에서 반복돼 8가지가 번갈아 나타난 것. 최대 연속 434회(약 2,170바이트)는
그 정도 구간은 물다가 미끄러진다는 뜻.

정렬이 한 번만 어긋나면 `find_pattern.py`로 맞추면 되지만, **도중에 계속 바뀌면
파일 전체에 적용할 단일 정렬이 없음.** 프리앰블은 7바이트마다 시작점을 다시
알려주므로 슬립이 나도 다음 프리앰블에서 회복됨.
