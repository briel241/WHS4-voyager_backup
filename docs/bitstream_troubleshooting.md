# 비트 스트림 송수신 트러블슈팅

`hello_tx` / `hello_rx_preamble` 구성에서 실제로 막혔던 것들.

## 점검 순서

위에서부터 봐야 시간 아낌.

```
1. 수신 스펙트럼에 봉우리 있나?      없으면 → tx_gain (②)
2. 성상도가 좌우 두 덩어리인가?      원이면 → 신호 약함/주파수 차이 (④)
3. Decoded message 가 나오나?       안 나오면 → 프리앰블 대조 (①)
4. 글자가 깨지나?                   → 엔디안 (③)
```

## ① 아무것도 출력 안 됨 — 프리앰블 불일치

송신 벡터 앞 2바이트와 수신기 access code가 비트 단위로 같아야 함.
하나만 바꾸면 검출 0건.

```
송신 Vector Source : [249, 168, ...]  →  0xF9 0xA8  →  11111001 10101000
수신 access_code   : '1111100110101000'
```

시뮬레이션 검증:

| 송신 벡터                            | 검출               |
| -------------------------------- | ---------------- |
| `[72,101,108,108,111]` (프리앰블 없음) | **0건**           |
| `[249,168,72,101,108,108,111]`   | 534건, 전부 `Hello` |

확인:

```bash
python3 -c "print(''.join(f'{b:08b}' for b in [249,168]))"
```

**블록 순서도 봐야 함.** 프리앰블 검출은 Differential Decoder 뒤에 있어야 함.
송신이 프리앰블까지 차동 부호화하므로 되돌린 뒤라야 원래 패턴이 보임.

## ② 수신 스펙트럼이 평평 — 송신 전력 부족

가장 흔함. `tx_gain` 0은 최소값이라 감쇠기 30 dB 지나면 잡음 아래로 내려감.

실측:

| tx_gain | 캡처      | 검출     | 최대 연속 | 분포                |
| ------- | ------- | ------ | ----- | ----------------- |
| 20      | 2.65 MB | **0건** | —     | 신호 없음             |
| 30      | 3.20 MB | 17,567 | 839회  | `████······` 앞부분만 |
| 40      | 0.43 MB | 6,270  | 434회  | `██████████` 전 구간 |

30은 건수가 많아 보이지만 캡처가 7배 큼. 밀도로는 40이 2.7배 우수하고
분포도 전 구간에 고름. **`tx_gain=40`, `tx_ampl=0.5` 채택.**

수신 스펙트럼에 봉우리 없으면 뒤쪽 블록은 전부 잡음 처리 중임.
뒤를 아무리 손봐도 소용없음.

## ②-2 find_pattern.py에서 8가지 정렬 전부 검출됨

정상이면 하나만 나와야 함. 전부 나오면 정렬이 캡처 도중 계속 바뀌는 것.

```
tx_gain 40   정렬0 5308 / 1 5936 / 2 5139 / 3 5079
             정렬4 5455 / 5 4984 / 6 5377 / 7 6270
```

Symbol Sync가 심볼을 가끔 하나 더/덜 세면(슬립) 그 순간부터 비트 경계가 1칸 밀림.
최대 연속 434회(약 2,170바이트)는 그 정도 물다가 미끄러진다는 뜻.

한 번만 어긋나면 `find_pattern.py`로 맞추면 되지만 도중에 계속 바뀌면
파일 전체에 적용할 단일 정렬이 없음. → 프리앰블이 필요한 이유.

## ③ 글자가 깨짐 — 엔디안

`Repack Bits` 기본값이 `LSB first`인데 송신 `Constellation Modulator`는
`MSB first`로 풂. 그대로 두면 바이트 안 비트가 뒤집혀 링크가 완벽해도 안 나옴.

```
Repack Bits → Endianness → gr.GR_MSB_FIRST
```

화면에 안 보이는 기본값이라 찾기 어려운 종류임.
`hello_rx_preamble.grc`는 Payload Console이 직접 MSB first로 묶어서 이 문제 없음.

## ④ 성상도가 둥근 원 — Costas 미잠김

BPSK 정상이면 좌우 두 덩어리. 원으로 퍼지면 반송파 위상이 안 잡힌 것.

1. 신호가 약함 → `tx_gain` / `rx_gain` 올림
2. 주파수 차이가 큼 → `center_freq` 낮춤 (157.2 MHz 약 125 Hz vs 1 GHz 약 800 Hz)

## ⑤ LookupError: No devices found

전력 문제로 보이지만 아님. 장치는 USB에 살아 있음.
UHD 프로세스 두 개가 동시에 USB를 스캔하면서 탐색이 충돌하는 것.

- 노트북 2대면 각자 자기 장비만 열어서 문제없음
- 한 노트북에서 두 프로세스면 5초 이상 시차
- **GRC 쓴 뒤엔 반드시 종료.** GRC가 B210 잡고 있으면 다른 프로그램이 조용히 실패함

```bash
pgrep -fl "gnuradio-companion|hello_"
```

## ⑥ GRC 탭이 빨간색

파일이 디스크에서 사라진 상태. 브랜치 전환하면 그 브랜치에 없는 파일은
작업 폴더에서 빠짐. 파일이 깨진 게 아님.

빨간 탭은 **저장하지 말고** 닫은 뒤 다시 열 것. 저장하면 메모리 상태로 덮어씀.

## ⑦ 파형이 직선/점 하나로 보임

수신 진폭이 0.001 수준이라 고정 축(±0.2)에서는 안 보임. 정상임.
감쇠기 30 dB와 낮은 송신 게인 때문.

- Time Sink → autoscale 켜기
- Constellation Sink → 앞단에 AGC
