# 구조·이름 대응표 (Stage 8 2-3 기능 중심 정리)

개발 순서를 가리키던 production 폴더·파일·내부 이름을 실제 기능·책임 이름으로 바꾼 결과다.
동작은 바꾸지 않았다. 이름과 경로만 바뀌었다.

기준: 브랜치 `feature/stage8-refactor-optimize`, 직전 구조는 커밋 `93bebbd`.

`stage7_b210_system_baseline.md`("B210 유선 시스템")다. 새 용어를 만들지 않고 프로젝트의
도메인 용어를 썼다. `testbed`는 이 패키지가 자격·운용 RF 경로를 그대로 담고 있어
"시험 전용"으로 읽힐 수 있어 쓰지 않았다 — 그것이 `testing/` 이름이 실제와 어긋났던 이유다.

## 5. 공개 호환 범위와 유지·제거 조건

### 5-1. PoC SDK 공개 경로

- **새 공식 경로**: `vdeter.poc.api` (및 하위 `codec`·`errors`·`limits`·`messages`·
  `negotiation`·`protocol`·`sdk`·`seams`·`transport`·`types`)
- **호환 유지**: 옛 경로 `vdeter.stage8.poc_api`와 그 하위 공개 module 10개가
  **같은 module·class·enum·함수 객체**를 가리킨다. 구현을 복제하지 않는다.
- **호환 제외**: `_supervisor`·`execution`·`integration`·`shared_medium`·`testing`은
  공개한 적이 없으므로 옛 경로로 열리지 않는다. 포괄 호환 package를 만들지 않았다.
- **검증**: `VDETER/tests/contract/test_stage8_import_boundary.py::PublicApiCompatAliasTest`가
  같은 객체·하위 module 전수 alias·비공개 비노출·bare import 시 하위 미적재·
  production의 새 경로 전용 사용을 계약으로 확인한다.

### 5-2. 문서화된 in-process seam

`build_stage7_b210_endpoint`는 `docs/사용법.md`·`docs/인수인계.md`가 "공식 in-process
연결점"으로 안내해 온 이름이라, `build_b210_endpoint`와 **같은 함수 객체**를 가리키는
alias로 남겼다.

### 5-3. 제거 조건 (날짜만으로 자동 제거하지 않는다)

1. 외부 사용자(외부 PoC 저자·링크 팀)가 새 경로로 전환했음을 확인하고,
2. 변경 안내를 공지한 뒤,
3. **별도 제거 승인**을 받는다.

세 조건이 모두 충족되기 전에는 호환 alias를 제거하지 않는다.

## 6. 자격 결속에 미친 영향

이번 작업은 **검증 정책을 바꾸지 않았다.** 기존 결속 규칙 아래에서 경로와 해시만 새 값으로
반영했다.

- reference 발급기의 `ENTRY_POINTS`·`FUNCTION_BOUND`·`CONFIG_ALLOWLIST`가 새 경로를 가리킨다.
  폐포 크기는 160개로 불변이다.
- coordinator의 자격 고정 함수는 소스 안에 spawn 대상 파일명 문자열과 패키지 import를
  담고 있어 해시가 바뀐다. 재고정은 **차이가 승인된 이름·경로 치환에 한정됨을 먼저
  입증한 뒤**, 이전 값과 새 값을 기록하고 수행했다.
- 과거 commit 대조는 **당시 경로**로 읽고 현재 경로와 분리했다. 과거 원문에는 승인된
  대응표만 적용한다(모든 차이를 무시하는 광범위 정규화가 아니다).
- 승인 범위 밖 변조를 거부하는 부정 대조 시험은 그대로 유지된다.

**수정 설치본은 기존 자격으로 운영할 수 없다.** 자격 재사용 판정은 rf·operation 영역이
byte-identical일 때만 성립한다. 이번 변경을 포함한 최종 안정본에서 재자격이 필요하다.
