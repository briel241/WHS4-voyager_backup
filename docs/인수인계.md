# MASS/ROC 응용 계층 — 인수인계

---

## 1. 브랜치에 올린 거?

- `feat/mass-roc-app` 브랜치에 **MASS(선박) ↔ ROC(육상) 응용 계층**을 올림.
- 원래 비어 있던 `MASS/`·`ROC/` 폴더를 실제 구현으로 채웠고, 두 쪽이 함께 쓰는 코드는 `common/`에 둠.
- 커밋·푸시·PR까지 완료.
- 링크·PHY 계층(`VDETER/`)은 안건드림.

---

## 2. 폴더 구조

```
common/   MASS·ROC 공유 (핵심)
  messages/   응용 메시지 7종 + registry
  codec.py    PI — 메시지 ↔ payload 바이트 변환
  coordinates.py bitfield.py navigation.py config.py
  outbound.py 송신 요청 / service.py API 어댑터
  security/   ECDSA·HMAC 서명 / observe/ 관찰 도구
MASS/     mass_agent.py   선박 행위자
ROC/      roc_agent.py    육상 행위자
docs/     시나리오·요구사항·설계 문서
tests/    시험 6종
apps/     실행 데모 3종
VDETER/   링크·PHY (건드리지 않음)
```

---

## 3. 핵심 내용

- MASS/ROC는 **payload(바이트)** 를 주고받음. 링크·전파는 `VDETER/`가 처리하고, 응용은 그 안을 모름.
- **PI(`codec.py`)** 가 응용 데이터 ↔ payload를 변환함. 봉투 구조:
  `[ VPFI 16bit | Message ID 8bit | 본문 | byte 패딩 ]`
- **메시지 7종**:
  위치보고 · 항로지시 · 응답(ACK) · AIS 인증값 · 항행경보 · 환경정보 · 기상관측
- 필드는 **실제 표준을 차용**했음 (AIS/IFM · S-124 · WMO BUFR · S-104/411/412).
  표준에 없는 것(자율운항 모드 등)만 직접 정의했고, 코드 주석에 그렇게 표시해뒀음.
- **행위자 둘**:
  - `MassAgent` — 항로 따라 움직이고, 위치보고 내보내고, 받은 항로·경보를 검증·반영함.
  - `RocAgent` — 항로 지시·AIS 인증값·항행경보를 만들어 내보냄.
  - 둘 다 `Outbound`(송신 요청)만 만들고, 링크에 어떻게 실리는지는 모름.

## 4. 테스트

```bash
# 시험 (전부 통과해야 정상)
python3 tests/test_mass_roc_messages.py       # 메시지 인코딩·디코딩
python3 tests/test_mass_roc_agents.py         # 행위자 동작
python3 tests/test_mass_roc_env_messages.py   # 경보·환경·기상 + 경보 방송→반영

# 데모
python3 apps/mass_roc_sim.py         # 정상 동작 시나리오 (관찰 보고서 생성)
python3 apps/warning_broadcast.py    # 육상국 경보 방송 → MASS 반영
```

> (후속으로 `VDETER/` 패키지 연동으로 바꿀 예정, §6 참고)

## 6. 해야 할 일

1. **`VDETER/` 연동** — 지금 통합 테스트·앱은 옛 로컬 사본(`VDETER_Link/`)을 참조함.
   GitHub의 `VDETER/`(vdeter 패키지, data session 포함)를 쓰도록 import를 바꿔야 함.
2. **시나리오 2개 선별** — 개발 대상 3개 중 인증서(SC-VDE-001)만 확정. 나머지 2개는
   서비스 카탈로그에서 고르고, 그중 하나(MASS 조작 데이터)는 멘토 자문 예정.
3. **Route Plan 기밀성** — S-421 항로는 노출되면 표적화 위험이 있어 암호화(SECOM)가
   필요할 수 있음. 인증만 할지, 암호화까지 할지 범위 결정 필요.
4. **환경·기상 메시지 행위자 연결** — 경보(§항행경보)와 같은 패턴으로 붙이면 됨.
