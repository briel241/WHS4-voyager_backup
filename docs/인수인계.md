# MASS/ROC 응용 계층 — 인수인계

`integration/mass-roc-certificate` 브랜치(구 `feat/mass-roc-app`을 최신 VDE-TER와

## 1. 확정 3개 시나리오 — 현황

| 시나리오 | 구현 | 재현·로그 | VDETER 종단 |
| --- | :-: | :-: | --- |
| **SC-VDE-001 X.509 인증서 송수신** | ✅ | ✅ | ✅ **소프트웨어 무선 종단** (Certificate Report + Data Session) |
| **SC-VDE-005 S-421 노선 계획** | ✅ | ✅ | ✅ **소프트웨어 무선 종단** (`sc_vde.route_control.command`, 실 codec) |
| **SC-VDE-006 MASS-ROC 원격 조종** | ✅ | ✅ | ✅ **소프트웨어 무선 종단** (노선과 같은 codec) |

- 원격 조종은 노선(S-421) 교환을 전제한 **하위 시나리오**임. 조종 데이터(heading
  setpoint·fallback·속도)를 노선지시(Message ID 2) 확장으로 실었고, 압축 코덱을
  왕복해도 필드가 보존됨을 확인함.
- **001·005·006 모두 소프트웨어 무선 종단됨.** 노선·조종은
  `sc_vde.route_control.command`/`.ack`(링크 팀 codec, TEST scope)를 쓴다.
  우리 인코더 출력이 링크 팀 시험 벡터와 바이트 단위로 일치함을 확인했다
  (`tests/test_sc_vde_contract.py`). 인증서(001)는 `x509.certificate_report`
  format과 Data Session 분할·재조립·ACK 경로를 사용하며 소프트웨어 무선 종단
  시험을 통과했다.
- ⚠ SC-VDE 두 포맷은 **서명·replay 보호가 없는 TEST 전용**이다(가이드 §8.5).
  격리 시험·데모에만 쓰고 실제 조타·actuator 구동에 쓰지 않는다.
- ✅ **SC-VDE 세 포맷이 링크 팀 main에 통합됐다** (2026-08-30, `2036cb2 Merge
  core/stage7-b210-system`). 중간보고 §2.1의 "Core 미통합"은 그 시점 기록이며 해소됐다.

요청 3건(① 시나리오 구현 ② 종료 로그·분석 ③ 선택·재현 인터페이스)은 세 시나리오
모두 코드·단위테스트·소프트웨어 종단 loopback까지 끝냈다. **B210 실물(3노드)
시나리오 시험은 별도 수행**한다.

**정량지표 3종도 실측한다** — 비인가 패킷 수용·인증 성공률·성능 저하.
`python tools/measure_metrics.py` 한 번이면 세 수치가 나오고 콘솔 GUI에도
실시간으로 뜬다. 세는 규칙과 그 수치의 한계는
[`docs/정량지표.md`](정량지표.md)에 적어 뒀다.

## 3. 핵심 구조

- MASS/ROC는 **payload(바이트)** 만 주고받음. 링크·전파는 `VDETER/`가 처리하고 응용은
  그 안을 모름. 행위자는 `Outbound`(payload·수신처·ACK 필요 여부)만 만듦.
- **메시지 두 계열이 있음**:
  - **계열 A (비트 패킹)** — 위치보고·항로지시·ACK·경보·환경·기상. `codec.py` 봉투
    `[ VPFI 16bit | Message ID 8bit | 본문 | padding ]`로 감쌈.
  - **계열 B (원시 payload)** — 인증서. `certificate_report.py`가 R1027 Certificate
    Report 본문을 만들고, VDETER가 포맷별로 직접 인식함. 우리 봉투 안 씀.
- **VDETER 연동**은 `vdeter_bridge.py`가 담당함. 우리 `Outbound`를 VDETER
  `SubmitTransferRequest`(`Addressed`/`StationId`/`PayloadFormat`)로 바꾸고, 수신
  `ReceivedApplicationData`를 응용이 다룰 `Inbound`로 폄. `data_type→payload_format`
  매핑은 5종 — x509 · AIS · SC-VDE 명령/ACK/위치보고. SC-VDE는 봉투를 떼고
  application bytes만 보내고, 길이·addressed 규칙을 submit 전에 검사함.
- 필드는 **실제 표준을 차용**했음 (AIS/IFM · S-124 · WMO BUFR · S-104/411/412 · S-421 ·
  ITU-R M.2092-2 §A4-4.15). 표준에 없는 것만 직접 정의하고 코드 주석에 표시함.
- **행위자 둘**: `MassAgent`(항로·경보 검증·반영), `RocAgent`(항로지시·인증값·경보 발행).

## 4. 실행 방법

Windows·Linux 공통으로 아래처럼 실행한다(`python`은 각자의 인터프리터 —
Windows에서는 `VDETER\.venv\Scripts\python.exe` 권장). 직접 실행 스크립트는
`common/textout.py`의 UTF-8 출력 정착을 쓰므로 `-X utf8`을 붙일 필요가 없다.

```bash
# 전체 pytest (구식 vdeter_link 시험은 Service API 회귀로 교체됨, ignore 불필요)
python -m pytest tests -q

# 단위 시험 (cryptography 없이도 도는 것들 — 전부 통과해야 정상)
python tests/test_mass_roc_messages.py        # 계열 A 메시지 인코딩·디코딩
python tests/test_mass_roc_agents.py          # 행위자 동작
python tests/test_certificate.py              # 인증서 생성·검증(대체 백엔드)
python tests/test_certificate_report.py       # Certificate Report 본문 코덱
python tests/test_scenario_runner.py          # 확정 3종 합격 판정
python tests/test_sc_vde_contract.py          # SC-VDE 계약 적합성(승인 벡터 일치)
python tests/test_metrics.py                  # 정량지표 계수 규칙
python tools/check_docs.py                    # 문서↔구현 정합 (상수·크기·registry·링크)

# Service API 종단 회귀 (소프트웨어 무선, cryptography 필요)
python tests/test_mass_roc_link_integration.py

# 정량지표 — 목표 3종을 실제로 측정한다 (docs/정량지표.md)
python tools/measure_metrics.py                          # 비인가 수용·인증 성공률·성능 저하
python tools/measure_metrics.py --transport software     # 무선 경유 (cryptography 필요)

# 시나리오 재현 인터페이스
python apps/scenario_runner.py list
python apps/scenario_runner.py run SC-VDE-001      # 인증서
python apps/scenario_runner.py run SC-VDE-005      # 노선
python apps/scenario_runner.py run SC-VDE-006      # 원격 조종

# 콘솔 GUI — 브라우저 두 창으로 ROC/MASS를 나란히 본다 (설치 불필요)
python apps/console_server.py
#   http://localhost:8420/roc    육상 관제 — 해도 클릭으로 항로 발행·원격 조종·정량지표
#   http://localhost:8420/mass   본선 — 상태·수신 로그·제어권(MON/RC) 표시

# 같은 콘솔에서 송신국 판정(방어)을 켠다. 기본값은 open — 표준의 현재 상태다
python apps/console_server.py --authority strict

# 같은 콘솔을 실 VDETER 소프트웨어 무선 스택 위에서 (cryptography 필요)
python apps/console_server.py --transport software
```

**전송 경로 세 가지** (`--transport`)

| 값 | 무엇을 지나나 | 쓸 때 |
| --- | --- | --- |
| `direct`(기본) | 무선 계층 없이 payload 직결 | 시연·관찰. 즉시 응답, 설치 불필요 |
| `software` (구 `vdeter`) | **실 VDETER Service API** (submit·status·HandlerServiceEventSink) 위 Software Radio | 응용↔링크가 실제로 맞물리는지 확인. 명령/ACK이 소프트웨어 무선을 왕복하므로 도착에 2~3초 걸림 |
| `stage7` | 외부(launcher/integration)가 조립한 Stage 7 Service를 **주입** | 실장비 통합. 콘솔 CLI 단독으로는 조립 불가 — `ExternalServiceTransport` 주입 seam 참조 |

`software` 경로는 loopback 데모와 같은 Service API를 쓴다. Stage 7 실장비 통합은
`console_transport.ExternalServiceTransport`에 Service를 주입하는 방식이다 —
공식 in-process seam은 `build_b210_endpoint(..., application_sink=...)`뿐이고,
별도 프로세스 launcher에 접속하는 응용 RPC는 공개 API에 없다(가이드 §15). 조립에
실패하면 사유를 찍고 `direct`로 내려간다.

> **위치보고도 VDETER를 탄다** — `sc_vde.position_report`(MF 1)로 등록됐다. 단
> `DR-PAYLOAD-016`에 따라 **addressed(MASS→ROC)·no-ACK 전용**이라 broadcast가 아니다.
> `ack_required=True`로 내면 `INVALID_REQUEST`로 거부되므로 transport가 이 포맷만
> `False`로 보낸다.

**VDETER 종단 시연**은 `cryptography` 설치된 인터프리터에서 돌려야 함(소프트웨어 무선
그룹 조립이 TBB 서명자 때문에 요구함). 없으면 스킵됨.

```bash
pip install cryptography
python apps/cert_loopback_demo.py       # 인증서 Data Session 종단(정상/위조)
python apps/route_loopback_demo.py      # 노선(005) 종단
python apps/control_loopback_demo.py    # 원격조종(006) 종단
python tests/test_cert_vdeter_integration.py     # 인증서 VDETER 실 codec 연동
python tests/test_mass_roc_link_integration.py   # Service API 종단 회귀
```

> 구 `VDETER_Link/`(스테이지 사본) 기반이던 `test_mass_roc_link_integration.py`는
> 실 `VDETER/` 패키지의 공개 Service API 회귀로 교체됐다. 별도 로컬 폴더 없이
> `pytest tests -q`가 ignore 없이 돈다. 링크 연동 기준은 `common/vdeter_bridge.py`다.

## 5. 남은 작업 (전부 외부 의존성 — 응용 계층에서 단독으로 더 할 요청 작업은 없음)

| 남은 일 | 성격 | 필요 조건 |
| --- | --- | --- |
| ~~노선·조종의 운영 VDETER 종단~~ | ✅ **완료** | 링크 팀 `feature/presentation-payloads` 병합으로 codec·registry 확보. 우리 코드는 수정 없이 자동 전환됨 |
| ~~SC-VDE-001 인증서 Data Session~~ | ✅ **완료** | `feature/certificate-data-session`의 구현·검증 결과를 통합하고 임시 admission gate와 미지원 분기를 제거했다 |
| **실 하드웨어 RF (B210)** | 링크 팀 | **감쇠기·Faraday Cage 불필요** — Pi 5 + B210 3대 SMA 직결 conducted testbed(C1~C6). **Stage 7 launcher도 생겼다**(`VDETER/apps/endpoint_launcher.py`, config는 `configs/b210_system/`). software 검증은 전체 PASS(`tools/run_stage7_tests.py`). 남은 것은 **하드웨어 판정 P0~P3** — 그 TC들은 실장비 실행 전까지 `NOT_RUN`이다 |
| **Route Plan 기밀성(선택)** | 범위 결정 | S-421 항로 노출 시 표적화 위험. 인증만 할지 암호화(SECOM)까지 할지 결정 필요 |

> **B-1 ACK 상관**은 불필요로 확정함. VDETER 수신 통지가 ACK를 원 노선 전송에 되묶는
> 상관 정보를 주지 않지만(설계상 전송 독립), 확정 3종은 미결 전송이 하나뿐이라 자명함.
> 논리 ACK는 이미 routeID·editionNo를 담고 있음. 다중 동시 노선까지 갈 때만 압축 ACK에
> routeRef를 더하면 되고, 이는 링크 팀 무관한 응용 선택임
> (`docs/archive/작업B_ACK상관_갭분석.md` — 당시 분석 기록. 그 문서는 압축 ACK가
> 상태 4bit만 나른다고 전제하나, 실제 ACK은 Linkage ID 10bit를 함께 나른다).

> **참고**: `codec.py`의 16-bit VPFI 봉투는 우리끼리 쓰는 내부 형식으로 남아 있다.
> VDETER로 보낼 때는 `codec.encode_body()`가 봉투 없는 application bytes를 만들고
> VPFI·Message Format은 VDETER가 붙인다(가이드 §8.2). 콘솔의 transport도 같은 규칙을
> 쓴다.

## 5.1 표준 대비 알려진 차이 — 결함이 아니라 범위

적합성 감사에서 나온 **동작 결함은 전부 수정됐다**. 아래는 남은 차이이며,
보고서·발표에서 실제보다 넓게 읽히지 않도록 여기 모아 둔다.

| # | 항목 | 표준 | 본 구현 | 상세 |
| :-: | --- | --- | --- | --- |
| 1 | **유효기간 기준 시각** | Table 13.2는 Start Date/Time부터 센다 | Duration을 **지시 수락 시각**부터 센다. Start 필드는 싣되 읽지 않는다 | [SC-VDE-005 §8.3](scenarios/SC-VDE-005-route-guidance.md) |
| 2 | **위치보고 수신 범위** | AIS 위치보고는 브로드캐스트 | 프로파일이 addressed 전용(`DR-PAYLOAD-016`). 행위자는 표준대로 broadcast로 만들고 구동기가 ROC 지정으로 바꾼다 | [SC-VDE-005 §9.2](scenarios/SC-VDE-005-route-guidance.md) |
| 3 | **X.509 검증 범위** | RFC 5280 전체 | 단일 CA·사전 탑재 앵커 전제. 폐기(CRL/OCSP)·KeyUsage·체인·Name 대조는 하지 않는다 | [SC-VDE-001 §6.3](scenarios/SC-VDE-001-x509-certificate.md) |
| 4 | **SC-VDE 형식의 보호 수준** | — | unsigned Segment Type 0 — 송신자 인증·무결성·replay 보호 **없음**. TEST 전용이며 실제 조타 구동에 쓰지 않는다 | 가이드 §8.5 |
| 5 | **인증서 Data Session** | — | 구현 완료. Certificate Report를 Data Session으로 운반하며 소프트웨어 종단 검증 완료 | [SC-VDE-001](scenarios/SC-VDE-001-x509-certificate.md) |

1·2·3은 **의도한 범위 축소**다. 1은 행위자가 UTC를 다루지 않아서(시험을
결정적으로 만들려는 선택), 2는 링크 프로파일 제약, 3은 신뢰 앵커를
out-of-band로 심는 전제 때문이다. 각각 어디를 고치면 되는지는 위 링크에 적어 뒀다.

> **대체 백엔드 주의** — `cryptography`가 없으면 HMAC 대체 경로로 내려간다.
> 흐름은 같지만 공개키 암호가 아니다. 성능·크기 수치는 반드시 표준 백엔드에서
> 측정한다 (검증 1건 125 µs vs 25 µs, 인증서 412 B vs 280 B).
