# MASS/ROC 응용 계층 — 인수인계

`feat/mass-roc-app` 브랜치. MASS(선박)↔ROC(육상) 응용 계층 + Presentation Interface를
구현하고, 확정 3개 시나리오를 VDETER 링크까지 종단 검증했음. 링크·PHY(`VDETER/`)는
팀원 담당이라 안 건드림.

---

## 1. 확정 3개 시나리오 — 현황

| 시나리오 | 구현 | 재현·로그 | VDETER 종단 |
| --- | :-: | :-: | --- |
| **SC-VDE-001 X.509 인증서 송수신** | ✅ | ✅ | ✅ **운영 종단** (소프트웨어 무선 왕복, 검증·저장·위조거부) |
| **SC-VDE-005 S-421 노선 계획** | ✅ | ✅ | ✅ 종단 왕복 · 계약 승인(`sc_vde.route_control.command`) — build에 codec 들어오면 운영 종단 |
| **SC-VDE-006 MASS-ROC 원격 조종** | ✅ | ✅ | ✅ 종단 왕복 · 노선과 같은 키 — build 대기 |

- 원격 조종은 노선(S-421) 교환을 전제한 **하위 시나리오**임. 조종 데이터(heading
  setpoint·fallback·속도)를 노선지시(Message ID 2) 확장으로 실었고, 압축 코덱을
  왕복해도 필드가 보존됨을 확인함.
- 노선·조종은 운영 payload_format이 VDETER registry에 아직 없어(링크 팀 등록 대기)
  운영 종단은 미완, 지금은 시험용 opaque 통과 포맷으로만 종단이 됨. 인증서는 운영
  포맷(`x509.certificate_report`)이 있어 운영 종단까지 됨.

요청 3건(① 시나리오 구현 ② 종료 로그·분석 ③ 선택·재현 인터페이스)은 위 3개
시나리오에 대해 코드·단위테스트·종단 loopback까지 모두 끝냈음.

## 3. 핵심 구조

- MASS/ROC는 **payload(바이트)** 만 주고받음. 링크·전파는 `VDETER/`가 처리하고 응용은
  그 안을 모름. 행위자는 `Outbound`(payload·수신처·ACK 필요 여부)만 만듦.
- **메시지 두 계열이 있음**:
  - **계열 A (비트 패킹)** — 위치보고·항로지시·ACK·경보·환경·기상. `codec.py` 봉투
    `[ VPFI 16bit | Message ID 8bit | 본문 | padding ]`로 감쌈.
  - **계열 B (원시 payload)** — 인증서. `certificate_report.py`가 R1027 Certificate
    Report 본문을 만들고, VDETER가 포맷별로 직접 인식함. 우리 봉투 안 씀.
- **VDETER 연동**은 `vdeter_bridge.py`가 담당함. 우리 `Outbound`를 VDETER
  `SubmitTransferRequest`(`Addressed`/`StationId`/`PayloadFormat`)로 바꾸고, 수신
  `ReceivedApplicationData`를 응용이 다룰 `Inbound`로 폄. `data_type→payload_format`
  매핑은 운영 지원 2종(x509·AIS)만.
- 필드는 **실제 표준을 차용**했음 (AIS/IFM · S-124 · WMO BUFR · S-104/411/412 · S-421 ·
  ITU-R M.2092-2 §A4-4.15). 표준에 없는 것만 직접 정의하고 코드 주석에 표시함.
- **행위자 둘**: `MassAgent`(항로·경보 검증·반영), `RocAgent`(항로지시·인증값·경보 발행).

## 4. 실행 방법

```bash
# 단위 시험 (cryptography 없이도 도는 것들 — 전부 통과해야 정상)
python3 tests/test_mass_roc_messages.py        # 계열 A 메시지 인코딩·디코딩
python3 tests/test_mass_roc_agents.py          # 행위자 동작
python3 tests/test_certificate.py              # 인증서 생성·검증(대체 백엔드)
python3 tests/test_certificate_report.py       # Certificate Report 본문 코덱
python3 tests/test_scenario_runner.py          # 확정 3종 합격 판정
python3 tests/test_sc_vde_contract.py          # SC-VDE 계약 적합성(승인 벡터 일치)

# 시나리오 재현 인터페이스
python3 apps/scenario_runner.py list
python3 apps/scenario_runner.py run SC-VDE-001      # 인증서
python3 apps/scenario_runner.py run SC-VDE-005      # 노선
python3 apps/scenario_runner.py run SC-VDE-006      # 원격 조종

# 콘솔 GUI — 브라우저 두 창으로 ROC/MASS를 나란히 본다 (설치 불필요)
python3 apps/console_server.py
#   http://localhost:8420/roc    육상 관제 — 해도 클릭으로 항로 발행·원격 조종
#   http://localhost:8420/mass   본선 — 상태·수신 로그·제어권(MON/RC) 표시
```

**VDETER 종단 시연**은 `cryptography` 설치된 인터프리터에서 돌려야 함(소프트웨어 무선
그룹 조립이 TBB 서명자 때문에 요구함). 없으면 스킵됨.

```bash
pip install cryptography
python3 apps/cert_loopback_demo.py       # 인증서 종단(정상/위조)
python3 apps/route_loopback_demo.py      # 노선(005) 종단(opaque)
python3 apps/control_loopback_demo.py    # 원격조종(006) 종단(opaque)
python3 tests/test_cert_vdeter_integration.py   # 인증서 VDETER 실 codec 연동
```

> `test_mass_roc_link_integration.py`와 일부 앱은 로컬 `VDETER_Link/`(구 스테이지 사본)를
> 참조함. gitignore돼 저장소엔 없으므로, 링크 연동은 `common/vdeter_bridge.py` + 위
> loopback 데모(실 `VDETER/` 패키지 사용)를 기준으로 보면 됨.

## 5. 남은 작업 (전부 외부 의존성 — 응용 계층에서 단독으로 더 할 요청 작업은 없음)

| 남은 일 | 성격 | 필요 조건 |
| --- | --- | --- |
| **노선·조종의 운영 VDETER 종단** | 링크 팀 의존 | **API 계약은 승인됨**(`sc_vde.route_control.command`/`.ack`, TEST scope). 우리 쪽 대응은 완료 — 매핑·봉투 제거·검증·적합성 시험까지 반영했고 승인 참조 벡터와 바이트 일치를 확인함. 남은 것은 **배포 build에 SC-VDE codec 포함**뿐(가이드 §17). 그때까지 loopback은 opaque로 자동 전환 |
| **실 하드웨어 RF 벤치 (B210 2대)** | 하드웨어 | 감쇠기 없음 → Faraday Cage 구축 대기 (`references/VDE-TER_Faraday_Cage_구축계획서.html`) |
| **Route Plan 기밀성(선택)** | 범위 결정 | S-421 항로 노출 시 표적화 위험. 인증만 할지 암호화(SECOM)까지 할지 결정 필요 |

> **B-1 ACK 상관**은 불필요로 확정함. VDETER 수신 통지가 ACK를 원 노선 전송에 되묶는
> 상관 정보를 주지 않지만(설계상 전송 독립), 확정 3종은 미결 전송이 하나뿐이라 자명함.
> 논리 ACK는 이미 routeID·editionNo를 담고 있음. 다중 동시 노선까지 갈 때만 압축 ACK에
> routeRef를 더하면 되고, 이는 링크 팀 무관한 응용 선택임 (`docs/작업B_ACK상관_갭분석.md`).

> **참고**: 계열 A 메시지가 나중에 운영 포맷을 받으면 `codec.py`의 16-bit VPFI 봉투는
> 빼야 함(VDETER가 VPFI를 소유). 지금은 노선/조종이 opaque(통과 포맷)로만 나가서 봉투가
> 무해하므로 손대지 않았음.
