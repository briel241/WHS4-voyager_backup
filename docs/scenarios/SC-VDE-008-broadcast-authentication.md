# SC-VDE-008 · 제약 채널 브로드캐스트 인증 (ECDSA vs TESLA)

> **설계·평가 시나리오**다. 앞선 SC-VDE-001~007이 "데이터가 조작되면 배에 무슨 일이
> 나는가"를 실증한다면, 이 문서는 **"그 조작을 어떻게 막는가 — 제약된 브로드캐스트
> 채널에서 인증을 어떻게 붙이는가"** 를 다룬다. 프로젝트 제목 뒷부분인
> **'암호통신 기술 개발'** 의 핵심 산출물이다.
> 
> 작성 형식은 [`TEMPLATE.md`](TEMPLATE.md)를 따르되, 데이터 흐름이 아니라 암호
> 메커니즘을 다루므로 §2·§5를 "방식 비교"로 대체한다.

---

## 1. 개요

| 항목          | 내용                                                                                     |
| ----------- | -------------------------------------------------------------------------------------- |
| 시나리오 ID     | `SC-VDE-008`                                                                           |
| 목적          | 제약된 브로드캐스트 채널(Link ID 11)에서 링크계층 브로드캐스트 인증을 어떻게 실현할지, 표준 방식(ECDSA)과 대안(TESLA)을 비교·평가한다 |
| 분류          | 소용량·일방적·주기적 브로드캐스트 (불리틴 보드 계열)                                                         |
| `data_type` | 해당 없음 — 링크계층 시그널링 (BBSC)                                                               |
| 위험 등급       | 상 (§6) — 무대는 SC-VDE-002(TBB 차단)를 빌린다                                                   |
| 상태          | **설계·평가 단계.** 무엇을 만들지 정의, 구현·시뮬레이션은 착수 전                                               |

### 1.1 왜 이 시나리오가 필요한가

[SC-VDE-002](scenario_list.md)에서 확인한 사실: **불리틴 보드(Type 20)는 표준에서
서명이 붙는 유일한 브로드캐스트 지점**이다. 그런데 그 브로드캐스트는 **Link ID 11에
강제**된다(M.2092-2 §A4-4.8.1, *"All transactions in the BBSC shall use Link ID 11"*).

동시에 인증 오버헤드는 packet보다 크다:

```text
불리틴 보드 인증 (Table 43)
   Digital Certificate Fingerprint     6 byte   (§A4-4.15)
   Authentication and integrity seq.  64 byte   (§A4-4.15, ECDSA 512 bit)
   ────────────────────────────────  ───────
   합계                                70 byte

Link ID 11 packet                       54 byte   (25 kHz · π/4-QPSK)
```

**인증 시퀀스(70 B)만으로 packet(54 B)을 넘는다.** 표준은 이를 **연속 fragment
(Type 21/22)로 쪼개** 여러 Link ID 11 슬롯에 나눠 실어 해결한다.

> ⚠️ 이전 판의 "ECDSA가 Link ID 11에 안 들어가므로 TESLA가 필요하다"는 결론은
> **부정확했다.** ECDSA는 **들어간다 — fragment로 쪼개면.** 문제는 "불가능"이 아니라
> **"비싸다"** 이다. 이 시나리오는 그 비용을 정량화하고 대안과 비교한다.

**왜 지금 만드는가 — 표준 암호는 언제나 "10년 뒤".** CPDLC 연구(Ziazi et al., USENIX
Security 2026)는 항공에서 표준 암호(DTLS) 배포가 2030년대 초 시험 예정이고, 표준 확정
후 실배포까지 10년 이상 지연됨을 지적한다. VDE-TER도 같다 — ECDSA는 §A4-4.15에 지정돼
있으나 PKI·키 배포·앵커 주입은 공란이고(§4.2 참조) 실배포는 요원하다. **그 공백 동안
쓸 브로드캐스트 인증을 지금 설계·평가하는 것**이 이 시나리오의 정당성이다.

## 2. 두 방식 비교 (§2·§5 대체)

### 2.1 방식 A — 표준 방식: 메시지별 ECDSA (M.2092-2 현행)

| 항목            | 값                                             |
| ------------- | --------------------------------------------- |
| 알고리즘          | ECDSA / secp256r1 / SHA-256 (§A4-4.15, 선택 불가) |
| 서명 크기         | 512 bit = 64 B + 지문 6 B = **70 B / 불리틴**      |
| Link ID 11 소요 | 70 B > 54 B → **연속 fragment로 ≥2 슬롯**          |
| 검증 비용         | 불리틴마다 **비대칭 서명 검증 1회** (수신 선박 모두)             |
| 시간 동기         | 불필요                                           |
| 인증 지연         | 없음 (수신 즉시 검증)                                 |
| 손실 내성         | fragment 하나만 유실돼도 해당 불리틴 인증 실패                |

### 2.2 방식 B — 대안: TESLA (지연 키 공개)

리포 내 논문 *Secure Maritime VHF Broadcast Authentication Using TESLA*
(Lee & Lee, IEEE Access, 2025.12)의 프레임을 따른다.

| 항목            | 값                                                  |
| ------------- | -------------------------------------------------- |
| 알고리즘          | 대칭 MAC + 해시 체인 기반 지연 키 공개                          |
| MAC 크기        | 논문 권장 **80 bit = 10 B / 메시지**                      |
| Link ID 11 소요 | 10 B + 키 공개(주기당 1회 상각) → **1 슬롯에 여유**              |
| 검증 비용         | **MAC/해시 검증** (비대칭 서명 대비 저렴)                       |
| 시간 동기         | **필요** — 느슨한 동기(loose sync)로 완화, 논문이 sync error 처리 |
| 인증 지연         | **키 공개까지 d 구간 지연** (권장 d=2, Tint=500 ms → 약 1 s)   |
| 손실 내성         | 해시 체인으로 이전 키 복구 가능 (loss-tolerant, TESLA의 'L')     |

### 2.3 핵심 트레이드오프

```text
             오버헤드    검증비용   인증지연   시간동기   비고
ECDSA        70 B/불리틴  높음(비대칭) 없음       불필요     표준. fragment 강제
TESLA        10 B/메시지  낮음(대칭)  d·Tint     필요       논문 권장 80b/500ms/d2
```

**한 문장 요약**: ECDSA는 지연 없이 즉시 검증하지만 제약 채널에서 슬롯·연산이 비싸고,
TESLA는 오버헤드·연산을 크게 줄이지만 시간 동기와 인증 지연을 대가로 치른다.

| 항목      | 값                                           |
| ------- | ------------------------------------------- |
| 물리 채널   | 25 kHz, π/4-QPSK (Link ID 11)               |
| Link ID | 11 (BBSC 강제)                                |

| 사전 조건   | 신뢰 앵커 탑재 (방식 A) / TESLA 키 체인 커밋먼트 배포 (방식 B) |

## 4. 평가 지표 (무엇을 측정하는가)

논문의 축을 우리 VDE-TER 파라미터에 적용한다.

| 지표          | 방식 A (ECDSA)       | 방식 B (TESLA)   | 측정 방법            |
| ----------- | ------------------ | -------------- | ---------------- |
| **인증 오버헤드** | 70 B + fragment 헤더 | 10 B + 키 공개 상각 | payload 계산 (구현됨) |
| **슬롯 소요**   | ≥2 Link ID 11 슬롯   | 1 슬롯           | Burst 크기 측정      |
| **인증 성공률**  | fragment 손실에 취약    | 해시 체인 복구       | 손실률별 시뮬레이션       |
| **인증 지연**   | 0                  | d·Tint (≈1 s)  | 파라미터 계산          |
| **위조 저항성**  | 서명 위조 불가           | 키 공개 전 위조 불가   | 공격 시뮬레이션         |
| **검증 연산**   | 비대칭 1회/불리틴         | 대칭 1회/메시지      | 상대 비교            |

## 5. 예상 결과

관찰 도구(`common/observe/`)로 대조군·비교군을 나란히 낸다.

- **오버헤드 그래프**: 불리틴 크기 대비 전파 나간 바이트. ECDSA는 fragment로 계단이,
  TESLA는 완만한 선이 나와야 한다.
- **손실률 vs 인증 성공률**: 버스트 손실을 키워가며 두 방식의 성공률 곡선. ECDSA는
  fragment 손실에서 급락, TESLA는 해시 체인으로 완만.
- **인증 지연 분포**: TESLA는 d·Tint 근처에 몰리고 ECDSA는 0.

**결론의 형태**: "VDE-TER Link ID 11 브로드캐스트에서 [조건]이면 [방식]이 유리하다"는
정량적 판정. 논문의 권장값(80b/500ms/d=2)이 우리 파라미터에서도 유효한지 확인.

## 6. 위험 (Risk) ★

이 시나리오의 위험은 **인증 방식 자체의 실패 모드**다. 무대는 SC-VDE-002(TBB)를 빌린다.

| 공격               | 방식 A에서                    | 방식 B에서                   | 등급       |
| ---------------- | ------------------------- | ------------------------ |:--------:|
| 데이터 위조           | 서명으로 차단                   | 키 공개 전이면 차단              | 낮음       |
| **키 공개 전 위조 시도** | 해당 없음                     | **지연 구간 악용 시도** → 논문이 방어 | 상        |
| **차단 (DoS)**     | fragment 하나 막으면 불리틴 인증 실패 | 키 공개 슬롯 막으면 해당 구간 실패     | **상**    |
| 재전송              | valid-until로 제한           | 키 공개 후 재전송은 무효           | 중        |
| 시간 동기 교란         | 무관                        | **동기 밀어 인증 창 조작**        | 상 (B 고유) |

- **직접/간접**: 간접. 브로드캐스트 인증이 뚫리면 슬롯맵·서비스영역이 위조돼
  **다른 공격의 발판**이 된다.
- **방식 B 고유 위험**: 시간 동기 의존성. TESLA는 "키 공개 시점 < 수신 시점"이라는
  보안 조건이 시간 동기에 걸린다. 동기를 밀면 인증 창이 열린다 — 논문이 다루는 지점.

`mass_roc_requirements.md`의 C-계열(암호 개발)에 대응한다.

| #   | 요구사항                   | 방식  | 담당               |

| C2  | TESLA 키 체인 생성·커밋먼트·MAC | B   | **암호 개발 (본 과제)** |
| C3  | 지연 키 공개 스케줄러 (Tint, d) | B   | 암호 개발            |

> **담당 경계 주의**: 표준상 불리틴 보드 서명은 **링크계층**(§A4-4.15, Type 20)의
> 책임이다. 그러나 **방식 비교·파라미터 선정·시뮬레이션 평가**는 링크 구현과 독립적으로
> 수행 가능하며, 이것이 '암호통신 개발'의 산출물이다. 실제 RF 링크 통합은 팀원과 협의.

## 8. 실패 조건

| 조건                     | 기대 동작                            |
| ---------------------- | -------------------------------- |
| ECDSA 서명 검증 실패         | 불리틴 폐기, §A4-4.15대로 수신 안 한 듯 처리   |
| TESLA MAC 불일치          | 해당 메시지 폐기                        |
| TESLA 키가 공개 시점보다 먼저 도착 | **보안 조건 위반 — 폐기** (동기 교란 방어의 핵심) |
| 키 공개 슬롯 유실             | 해시 체인으로 다음 공개에서 소급 복구 시도         |

## 9. 로그 내용

| 항목                     | 용도             |
| ---------------------- | -------------- |
| 방식 (ECDSA / TESLA)     | 대조군 구분         |
| 불리틴 크기 · 전파 바이트 · 슬롯 수 | 오버헤드 비교        |
| MAC/서명 검증 결과           | 인증 판정          |
| 인증 지연 (수신→검증 시각차)      | 방식 B 평가        |
| 키 공개 시각 · 수신 시각        | TESLA 보안 조건 확인 |
| 손실 여부 (delivered/lost) | 성공률 곡선         |

### 9.1 미해결 사항

1. **TESLA 링크계층 구현 담당** — 표준 밖 대안이므로 팀원(링크)과 본 과제(암호) 중
   누가 어디까지 구현하는지 미확정. 최소한 시뮬레이션 평가는 본 과제.
2. **VDE-TER 파라미터로의 Tint 재조정** — 논문 권장 500 ms가 Link ID 11 프레임
   구조(1분 프레임 단위)와 맞는지 확인 필요.
3. **SECOM(IEC 63173-2)과의 계층 관계** — 논문은 TESLA(링크) + SECOM(응용) 조합을
   제안한다. 우리 PI 계층이 SECOM 역할을 겸하는지 검토 대상. → `mass_roc_background.md`
