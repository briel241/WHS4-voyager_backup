# 개발 대상 시나리오 목록

> MASS/ROC가 VDE-TER로 주고받는 데이터를 시나리오 단위로 정리한다.
> 작성 형식은 [`TEMPLATE.md`](TEMPLATE.md)를 따른다.

프로젝트 제목 **"보안성 검토 및 암호통신 기술 개발"** 의 두 목적이 두 축이 된다.

| 축                   | 답하는 질문                            | 정렬 기준        |
| ------------------- | --------------------------------- | ------------ |
| **보안성 검토** (영향 실증)  | 데이터가 조작·차단되면 **배에 무슨 일이 나는가**     | **위험(Risk)** |
| **암호통신 개발** (방어 설계) | 그 조작을 **어떤 암호로 막고, 우리가 무엇을 만드는가** | **암호 메커니즘**  |

## 0. 확정 개발 대상 — 3개 시나리오

개발 대상은 **아래 3개로 확정**됐다. 005·006은 응용 계층 구현·단위시험·소프트웨어
무선(Software Radio) 종단까지 완료됐고, 001은 응용 코드만 보존된 채 실제 VDE-TER
Data Session이 미완성이라 **현재 미지원**이다(사용법: [`../사용법.md`](../사용법.md),
현황: [`../인수인계.md`](../인수인계.md)). B210 실물(3노드) 시험은 셋 다 아직이다.

| 시나리오 | 데이터 | 상태 |
| --- | --- | --- |
| **SC-VDE-001** 공개 키 인증서 송수신 | ITU-T X.509 v3 인증서 | ⛔ 현재 미지원 — 응용 코드·코덱 보존, Data Session 미완성 |
| **SC-VDE-005** 노선 계획 교환 | S-421 (S-100) Route Plan | ✅ 소프트웨어 무선 종단 (sc_vde format, TEST scope) |
| **SC-VDE-006** MASS-ROC 원격 조종 | S-421 조작 데이터(heading·fallback·SOG) | ✅ 소프트웨어 무선 종단 (SC-VDE-005 하위) |

- **SC-VDE-006(원격 조종)** 은 노선(S-421)이 교환된 상황을 전제한 **하위 시나리오**다.
  ROC가 heading setpoint·fallback·속도 조정을 지시하고 MASS가 검증·반영한다. 조작
  데이터를 노선지시(Message ID 2) 확장으로 실었다(압축 비트).
- 아래 §1·§2는 **이 3개를 왜 골랐는가**의 분석 근거(서비스 인벤토리·암호 메커니즘)이며,
  §3~§4는 전체 시나리오 풀과 후속 후보를 함께 정리한다.

### 0.1 두 축은 SC-VDE-001에서 만난다

데이터 축("어떤 데이터를 쓰나")과 암호 축("어떻게 지키나")은 **인증서 송수신
(SC-VDE-001)** 에서 만난다 — 인증서가 나눠준 공개키가 다른 모든 서명 검증의 기반이기
때문이다. 즉 SC-VDE-001이 이 프로젝트 "암호통신 개발"의 핵심 산출물이다(실 ECDSA
P-256/X.509).

**실증 원칙 — 풀스택으로 보인다.** 공격 실증은 비트 주입이 아니라 **실물 링크·RF를
통과**해야 성립한다 — 동형 체계(항공 CPDLC) 공격 연구(Ziazi et al., USENIX Sec 2026)가
"응용 계층만으론 부족하다"를 확인했다. 링크 계층 팀원과의 협업 지점이다.

> 근거: IALA G1117(VDES 활용 시나리오) · IALA *Use Cases on VTS Digital Communications* ·
> ITU-R M.2092-2 · `../vdeter_mass_roc_api_guide.md` · 구상도 · CPDLC 공격 논문(Ziazi et al., USENIX Sec 2026)

## 1. 서비스별 데이터 인벤토리 (선정 근거)

IALA G1117의 VDES 활용 시나리오에서 서비스를 뽑아, 각 서비스가 쓰는 데이터·규격·침해
파급력을 정리한다. **이 표가 시나리오 선정의 근거였다** — 규격이 잘 정의됐고 파급력이
높은 데이터일수록 우선순위가 높다.

| 서비스              | 규격            | 규격 완성도         | 기밀성 파급 | 무결성 파급 | 대응 시나리오              |
| ---------------- | ------------- | -------------- |:------:|:------:| -------------------- |
| **노선 계획 교환**     | **S-421**     | Ed.1 발행 완료     | **상**  | **상**  | **SC-VDE-005 ✅확정 / 006 하위** |
| **공개 키 인증서 송수신** | X.509         | —              | —      | **최상** | **SC-VDE-001 ✅확정**   |
| 선박통항관제(VTS)      | S-212         | 0.7.3 개발 중     | 중      | 상      | 후속 (표준 미완성)          |
| 물류·항만 서비스        | S-211         | Draft (1.0.0)  | **상**  | 중-상    | 범위 밖 (항행안전 밖)        |
| 항행 경보            | S-124         | Ed.2.0.0 발행 완료 | 하      | 상      | 부분 구현 (메시지·행위자)      |
| 실시간 기상·조석        | S-104/411/412 | 일부만 운용판        | 하      | 상      | 부분 구현 (메시지)          |
| 선박 기상관측 보고       | BUFR          | 상용 중           | 중      | 중      | 부분 구현 (메시지)          |

### 1.1 두 가지 발견

**① 무결성은 데이터 종류와 무관하게 높다.** 선박 한 척의 가치가 억 단위이고, 그 배가
주고받는 데이터가 변조되면 파급력이 작을 수 없다. → **무결성(인증)이 프로젝트의 1차
관심사**인 근거. 확정 시나리오가 인증서 송수신인 것과 맞물린다.

**② 기밀성은 데이터에 따라 갈린다.**

- **방송 안전정보**(경보 S-124, 기상 S-104)는 기밀성 **하** — 원래 공개돼야 하는 정보.
- **개별 선박 정보**(노선 S-421, 화물 S-211)는 기밀성 **상** — 노출되면 **표적화**된다.

노선·기항 정보 노출이 선박 공격으로 이어지는 관계는 실제 사례로 뒷받침된다(2024~2026
후티의 선박 공격에서 기항 이력·운항 방향이 표적 선정에 활용된 정황, 특히 공격 회피를
위해 선박들이 AIS를 끄기 시작한 정황). 즉 **Route Plan에는 무결성뿐 아니라 기밀성도
요구된다** — 인증만으론 부족하고 **암호화가 필요할 수 있다**(§6 미해결).

### 1.2 왜 S-421 Route Plan을 골랐나

| 근거               | 내용                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------- |
| **use case 정리도** | IALA *VTS Digital Communications* Use Cases에서 **Route Function이 가장 잘 정리**됨(다른 기능은 미정리) |
| **규격 완성도**       | S-421 Ed.1 발행 완료 → 데이터 교환의 프로토콜 문제를 파악하기 좋음                                            |
| **기밀성 근거**       | 노선 노출 → 표적화 관계가 성립 → 기밀성 보장의 필요가 실증됨                                                   |

SC-VDE-005(항로 지시·추종)가 이 데이터를 다루고, SC-VDE-006(원격 조종)이 그 위의 조작
데이터를 다룬다.

### 1.3 직접 위험과 간접 위험 (실증 방법의 구분)

- **직접 위험** — 조작하면 배가 즉시 다르게 움직인다. 관찰 도구 **항적 한 장**으로 끝난다.
  (항로 지시·원격 조종·전자해도)

- **간접 위험** — 조작하면 **다른 공격이 가능**해진다. 직접 시나리오를 무대로 빌리는
  **2단 실증**이 필요하다. (인증서·AIS 인증값)

  > 인증서가 오염되면 → 위조 명령이 통과하고 → **배가 항로를 벗어난다.**

## 2. 암호 메커니즘 인벤토리 (두 번째 축)

표준에서 뽑은 암호 지점과, 각 지점에서 **공격할 것 / 개발할 것**을 정리한다.

| 암호 메커니즘             | 표준 상태 (M.2092-2)                           | 여기서 하는 일                 | 성격     |
| ------------------- | ------------------------------------------ | ------------------------ |:------:|
| **PKI·인증서 배포**      | CA·키 배포·앵커 주입 **공란**                       | ★ X.509 인증서 송수신·검증 구현 (SC-VDE-001) | **개발** |
| **인증 부재 (CIV)**     | Type 4/90/13/92/93 서명 필드 **0개**            | ★ 위조·사칭 실증 (SC-VDE-005/006 무대) | 공격     |
| 서명 검증 우회            | ECDSA 있으나 valid-until 창 존재                 | 유효기간 내 재전송, 48비트 지문      | 공격     |
| CRL 오프라인 창          | "CA 불가 시 CRL 저장" 요구                        | 폐기 키 계속 신뢰 구간            | 공격     |
| 물리·행위 기반 탐지         | 표준에 없음                                     | 송신원 정합성·이상 탐지 (관찰 도구 확장) | 방어     |

> ★ 표시가 **택한 개발·공격 초점**이다. 나머지는 후속 확장 대상.
> 맨 끝 행은 CPDLC 연구의 시사점 — 표준 암호 배포가 "10년 뒤"라, 그 공백을 메울 중간
> 방어로 RF 지문·위치 정합성 검사가 제시된다. 우리 관찰 도구가 그 초기 형태다.

### 2.1 확정된 암호 사실 (표준 원문 확인)

- **M.2092-2는 ECDSA 일변도** — 암호 파라미터는 §A4-4.15가 고정(secp256r1·SHA-256·
  P1363·지문 48 bit). SC-VDE-001이 이를 그대로 구현했다.
- **BBSC는 Link ID 11 강제** (§A4-4.8.1). 불리틴 인증 = 지문 6 B + ECDSA 64 B = 70 B >
  packet 54 B → 연속 fragment 분할.

## 4. 확정 3개 시나리오 요약

### SC-VDE-001 · 인증서·CRL 전송 ⛔ 확정 · 현재 미지원

상세: [`SC-VDE-001-x509-certificate.md`](SC-VDE-001-x509-certificate.md)

- **행위**: ROC가 인증서 전송 → MASS가 재조립·검증 후 신뢰 저장소 반영
- **데이터**: X.509 DER 최대 1,024 B → Link ID 17에서 **6 fragment**
- **암호 지점**: **CRL 오프라인 창**. 서명 안 깨고 갱신만 막으면 폐기 키 계속 신뢰
- **간접**: 영향은 SC-VDE-005를 무대로 (오염 인증서 → 위조 항로 통과)
- **상태**: 응용 코드(발급·검증·코덱)와 단위시험은 보존. 실제 VDE-TER **Data
  Session이 링크 계층에서 미완성**(`data_session_enabled=false`)이라 운영 실행은
  미지원 — 인증서 브랜치 완성 후 재개한다. 소프트웨어 loopback으로 응용 계층
  검증(정상 검증·저장 / 위조 거부)만 참고 확인했다.

### SC-VDE-005 · 항로 지시와 추종 ✅ 확정 (S-421)

상세: [`SC-VDE-005-route-guidance.md`](SC-VDE-005-route-guidance.md)

- **행위**: ROC가 항로를 지시한다 → MASS가 검증하고 수락한다 → MASS가 항로를 따라간다
- **암호 지점**: **인증 부재**. Type 92는 segment 계층 밖이라 서명이 없다.
- **공격**: ROC MMSI를 **사칭**해 위조 항로 주입 → 항적 이탈
- **상태**: 항로지시(ID 2)+ACK(ID 3) 구현. 압축 코덱 왕복 + 종단 loopback 확인

### SC-VDE-006 · MASS-ROC 원격 조종 ✅ 확정 (S-421 하위)

상세: [`SC-VDE-006-remote-control.md`](SC-VDE-006-remote-control.md)

- **행위**: 노선 교환을 전제로 ROC가 조종 명령(heading setpoint·fallback·속도) 발행 →
  MASS가 검증·반영 → S-421 상태코드 ACK
- **데이터**: `mass_roc_control_and_ack_message_format.md`의 조작 데이터·ACK 형식.
  route_instruction 확장(heading·fallback·turn radius·SOG·leg)으로 실음(압축 비트)
- **상태**: 조종 필드가 압축 코덱을 왕복해도 보존됨을 확인 + 종단 loopback

## 5. 후속 시나리오 (참고)

확정 3종 밖의 시나리오. 구현·설계 상태만 요약한다.

- **부분 구현 (메시지·행위자)** — 항행 경보(S-124, ID 5, 방송→반영까지) · AIS 인증값
  (IEC 63173, 82 B, 공격 5종 검증). 환경(S-104/411/412, ID 6)·기상(BUFR, ID 7)은 메시지만.
- **미착수 (링크 계층 대기)** — 전자해도(S-101, 대용량 data session) · TBB 브로드캐스트
  (표준에서 서명이 붙는 유일한 지점, BBSC=Link ID 11).
- **설계만 (후속)** — 제어권 전환·비상 원격 개입(표준 메시지 없음, 프로젝트 정의 필요) ·
  제약 채널 브로드캐스트 인증(ECDSA vs TESLA 비교, 링크 RF 독립 시뮬 평가 대상).

### 5.1 실증 짝짓기

| 3   | B210 실물시험 (3노드)            | Pi 5 + B210 3대 SMA 직결 conducted testbed 준비됨 — 실물 실행 대기 | 프로젝트 · 링크    |

**2번은 방향을 가르는 결정이다.** 지금까지 프로젝트는 **무결성(인증)** 에 집중했다 —
대부분 데이터가 "숨길 필요는 없지만 위조되면 안 되는" 방송 정보였기 때문이다. 그러나
**Route Plan(S-421)은 기밀성도 상**이다(노선 노출 → 표적화, §1.1). 이 데이터를 쓰면
**서명(무결성)만으로는 부족하고 암호화(기밀성)가 필요**해진다. SECOM(IEC 63173-2)이
응용 계층 종단 암호화를 제공하므로, 이를 범위에 넣을지 결정해야 한다.
